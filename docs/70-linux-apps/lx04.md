# LX04 · pthread 互斥量与条件变量如何正确配合？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

互斥量保护共享条件；条件变量用于等待条件可能变化。等待必须在 while 循环里重新检查 predicate，不能把 signal 当一次可靠消息。修改条件与检查应使用同一锁规则。

## 原理拆解

pthread_cond_wait 原子地释放 mutex 并等待，返回前重新取得 mutex。虚假唤醒与多个等待者竞争要求重新检查。通知不是数据，发通知时没有等待者可能不会留存，持久条件保存在共享状态。

## 例子与推演

生产者在锁内入有界队列并通知；消费者 while(queue.empty()&&!stop) wait；stop 也在锁内设置并广播。退出时决定剩余数据是消费完还是丢弃，再 join 工作线程。

## 常见误区与失败边界

if 代替 while 可能在虚假唤醒后访问空队列。只通知不改 predicate 会丢逻辑；销毁锁/cond 前需确保没有线程再访问。

## 面试追问

signal 必须在锁内吗？答：关键是 predicate 与等待协议保持正确同步；工程上常锁内修改并有清楚通知时机，不能只背位置。

## 动手练习与验收

测试空、满、停止、多个消费者和广播。验收：无无界等待，所有线程可 join，测试成功不替代同步模型证明。
