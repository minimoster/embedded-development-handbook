# LX01 · 进程、线程和虚拟地址空间怎么区分？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

进程是资源与地址空间的重要边界，线程共享同一进程的许多资源但有独立执行状态和栈。每个进程的同样虚拟地址不代表同一物理内存；共享需显式机制。

## 原理拆解

MMU 与内核管理地址映射和权限。线程共享堆、全局变量及通常的文件描述符表，因此更容易出现数据竞争；栈私有不代表栈中的指针指向私有数据。fork 后写时复制也是逻辑独立，不能直接当共享通信。

教科书创建/就绪/运行/阻塞/终止用于解释转换，Linux观测状态则不能一一照抄。/proc/PID/stat的R涵盖运行或可运行，S为可中断睡眠，D为不可中断等待，Z为僵尸等；唤醒通常先变为可运行，不等于立刻获得CPU。僵尸已结束执行但保留可供父进程等待回收的信息，不能把全部终止状态当作资源已经完全回收。

## 例子与推演

两个线程各有本地指针，但都指向同一 buffer，修改仍需同步。多个进程通过 mmap 的共享映射通信，则需要进程共享同步协议，而不是直接拿普通线程局部锁。

## 常见误区与失败边界

“线程只有栈不同”是过度简化，调度、TLS、信号掩码等也需区分。Linux 线程与 MCU 任务可类比执行上下文，但地址隔离不能混讲。

Linux NPTL 的用户态 pthread 通常对应内核调度实体，可在多核运行；这与纯用户级协程的调度模型不同。每线程有独立管理的栈/TLS/执行状态，却不因“自己的栈”获得同进程其他线程无法访问的硬件隔离。正常 pthread_exit 不等于 exit 整个进程；进程创建与回收另见 [LX13](lx13.md)。

## 面试追问

地址相同能证明同一数据吗？答：不行，需结合进程/映射；地址不同也可能映到同一共享物理页。

## 动手练习与验收

画进程与线程内存图，标每个数据的共享者。验收：能解释所有权、权限、生命周期与同步四件事。
