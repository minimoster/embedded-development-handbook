# LX07 · IPC 的 pipe、socket 和共享内存怎么选？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

按通信方向、消息/字节语义、是否跨机器、数据量和生命周期选 IPC。pipe 通常是字节流；socket 提供多种域/类型；共享内存减少复制潜力但同步、格式与恢复由应用承担。

## 原理拆解

共享内存不是自动零成本，cache 竞争和同步仍有开销。Unix domain socket 可用于本机进程边界，TCP 用于网络但同样需应用帧。IPC 协议应版本化，不能直接传含进程本地指针的 struct。

## 例子与推演

采样进程→处理进程可用共享环形区加通知 fd；低频配置消息可用 Unix socket，更容易封装边界和错误。重启后老共享段需检查 epoch，避免把旧状态当新消息。

## 常见误区与失败边界

把地址值发送给另一进程不能让其合法解引用。一个 IPC 机制提供原子写部分保证，也不意味着任意大消息或多字段更新原子。

消息队列保留消息边界也有容量限制；它只提供队列操作的同步语义，不自动处理应用协议、共享对象、多消息事务、背压和崩溃恢复。“最快IPC”需结合数据量、复制、缓存竞争和通知成本测试，不能按类型固定排名。pipe字节流的PIPE_BUF原子写范围也不等于一次读恰好得到一条业务消息。

## 面试追问

共享内存生产者崩溃怎么办？答：设计状态、拥有者恢复、版本/epoch 和超时；不能永远等“正在写”。

## 动手练习与验收

为小控制消息和大图像帧各写选择表。验收：明确复制、同步、背压、权限和重启恢复，不仅比较速度。
