# LX05 · mmap 共享内存、文件映射和持久化的边界？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

mmap 将文件或匿名内存映到地址空间，MAP_SHARED 与 MAP_PRIVATE 的更新可见性不同。映射不自动解决同步，文件数据变化也不等于已经耐久落盘。使用前核对长度、offset、权限和错误返回。

## 原理拆解

映射访问仍需合法范围；文件被截断后访问可能触发 SIGBUS。映射存活与 fd 生命周期不应混淆；munmap 后所有指向该区域的视图失效。共享内存协议需定义发布顺序和 crash 恢复。

## 例子与推演

生产者写 payload 再发布 sequence，消费者验证版本与长度；共享的原子/锁实现必须支持进程共享。对于 MMIO 不能把普通文件 mmap 的 cache/顺序假定套上，应使用受支持驱动接口。

## 常见误区与失败边界

MAP_PRIVATE 改写不等于写回文件。把用户空间虚拟地址直接交给设备做 DMA 错误；这涉及内核映射与驱动接口。

MAP_SHARED 文件映射同样需要线程/进程同步协议；文件系统权限不自动让并发读改写成为事务。MAP_PRIVATE 修改与共享可见性也不同。同步、对象生命周期与持久化分别列验收，不能只因用了 mmap 就省掉锁或掉电验证。

## 面试追问

mmap 一定比 read 更快吗？答：页缺失、访问模式、同步和复制路径不同，需在真实工作负载测量。

## 动手练习与验收

用临时文件比较 shared/private 可见性并严格限制映射长度。验收：MAP_FAILED 处理正确、释放后不访问，不宣称此实验验证持久化电源故障。
