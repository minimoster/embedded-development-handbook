# LX11 · 系统调用、库函数与用户态/内核态有何不同？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

系统调用是用户程序请求内核服务的受控入口，库函数可能封装系统调用，也可能完全在用户态处理。驱动内核代码不能直接使用用户态libc，因为环境、ABI、内存与安全约束不同。

## 原理拆解

调用需要校验参数与权限，并在内核执行相应服务；不是每个函数名都一一对应一个syscall。stdio带用户缓冲，而read/write是fd接口，混合使用需协调缓存与offset。内核分配/日志/用户复制使用相应内核API。

## 例子与推演

printf可能只把数据放入stdio缓冲，write把字节送给fd的内核接口，二者都不自动表示远端业务确认/磁盘掉电持久。驱动用printk/dev_*日志也需节流，不拿printf直接链接。

## 常见误区与失败边界

“用户态不能访问硬件所以只能写驱动”忽略已有子系统接口；应用应优先用已暴露设备API，不绕到/dev/mem。

strlen等库函数可完全在用户态完成，stdio可有用户缓冲；并非所有库函数都有缓冲或跨平台合同。read/write是系统调用接口，但内核也可能使用页缓存/设备队列，不是“无缓冲且立即持久化”的保证。RTOS名称也不自动给应用最坏deadline保证，Linux可配置实时调度/PREEMPT_RT，需看配置、阻塞、IRQ及实际证据。

## 面试追问

strace看不到纯计算为何？答：它主要观察系统调用与信号，不是函数级CPU profiler。

## 动手练习与验收

观察受控程序buffered与unbuffered输出边界，画请求/返回图。验收：不把C标准函数和内核API混用，理解权限边界。
