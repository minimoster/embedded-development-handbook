# LX16 · 页表、TLB、缺页和 COW 如何解释虚拟内存？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

虚拟内存首先是地址映射和保护机制，不要求一定有交换磁盘。页表描述虚拟页到物理页及权限，TLB 缓存地址翻译结果；TLB 未命中不等于缺页。缺页可能是正常按需分配、COW 或文件加载，也可能是无权限/非法访问。只有处理路径无法合法满足访问时，才进入相应错误处理。

## 原理拆解

在常见有 MMU 的 Linux 模型中，CPU 产生虚拟地址，MMU 利用 TLB/页表取得翻译与权限。架构可能采用不同 cache 索引方式，不应把“MMU 先、cache 后”画成所有处理器固定串行电路。

TLB miss 可以通过有效页表完成翻译而不陷入用户可见错误；缺页则涉及页是否存在、可否访问和内核能否补齐。匿名页面首次写可能分配物理页；fork 后对 COW 页面写入可能复制页面；文件页未驻留可能需要读入。无 swap 的系统同样能拥有不同进程地址空间。

MAP_PRIVATE 的文件映射修改通常形成私有 COW，不等于更新其他进程或文件；MAP_SHARED 可共享修改，但还要设计同步、生命周期与持久化。x86 分段/线性地址术语须限定模式；不能推出 ARM DMA 地址恒等 CPU 物理地址。

## 例子与推演

父进程有变量 count=3，fork 后孩子把它改为 9：父进程的 count 仍为 3，因为逻辑地址空间独立。若双方改为访问相同 MAP_SHARED 区域，则可共享该区域的数据，但读写顺序仍由同步协议保证。

某进程虚拟空间很大而 RSS 很小，可能是地址范围已预留而大部分页未触碰；不是“系统已经给它装满同样大的物理 RAM”。要结合映射、RSS、故障计数和访问行为判断。

## 常见误区与失败边界

“虚拟内存=RAM+磁盘”会遗漏隔离和权限。“页不在 RAM 时先把这个页从 RAM 移出”逻辑颠倒：应处理目标页的合法缺页并可能先回收其他页。缺页不是段错误同义词。

3G/1G 是某些 32 位配置示例，不能给 AArch64、不同内核配置或安全隔离方案定律化。const 对象的实际段布局也不是 C/C++ 语言保证。共享映射不自动解决数据竞争，更不自动解决掉电持久化。

## 面试追问

问：关 swap 后还有虚拟内存吗？答：通常仍有映射与隔离。
问：两个进程地址相同为什么不共享变量？答：页表和映射关系可不同。
问：TLB 与数据 cache 有何差别？答：前者缓存翻译，后者缓存数据/指令；维护和权限问题不能混说。

## 动手练习与验收

在自建主机测试中分配映射但暂不触碰，再逐页访问，比较映射信息、RSS 与 getrusage 的缺页统计。单独对比 MAP_PRIVATE 与 MAP_SHARED 的父子写入结果，并给共享数据加明确同步。

验收：逐阶段写清哪些结论来自 API、哪些来自实测；能解释 TLB miss、minor/major fault、SIGSEGV 的区别。Linux 页大小需实际查询，不把 4 KiB 当所有系统常量；不宣称已检查实板页表。
