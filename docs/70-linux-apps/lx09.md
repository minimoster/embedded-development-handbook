# LX09 · join、detach、退出与资源回收怎么设计？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

join等待线程结束并获取适用结果；detach允许线程资源在结束后自动回收，但不能再以join管理其生命周期。detach不代表线程访问的对象自动保持存在，也不等于安全关闭。

## 原理拆解

工作线程持有ctx/buffer/fd时，拥有者必须等待它不再使用后释放。停止标志需要合法同步，并唤醒阻塞等待；仅设置一个未同步bool无法保证退出。异常/失败路径也应统一关闭。

## 例子与推演

服务创建3个worker，其中第3个创建失败，应通知前2个停止并join，再释放共享队列。后台detach线程如果引用局部对象会悬空，因此长期任务需要明确拥有者与停止协议。

## 常见误区与失败边界

“detach防止泄漏所以到处用”会失去完成协调能力。pthread函数常直接返回错误码，不能统一按errno处理。

## 面试追问

主线程退出其他线程一定继续吗？答：进程退出与当前线程退出不同，需区分return main/exit与线程终止接口。

## 动手练习与验收

主机演练部分创建失败、阻塞退出和重复停止。验收：线程不访问已释放ctx，所有joinable线程最终join。
