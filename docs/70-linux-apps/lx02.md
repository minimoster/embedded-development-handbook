# LX02 · read/write 的短读、短写与 EINTR 如何处理？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

read/write 返回实际传输的字节数，可能小于请求。循环需要推进 offset 并正确处理 0、EINTR、EAGAIN 和真实错误；阻塞语义依对象和 flags，不同文件类型的 0 返回要按 API 合同解释。

## 原理拆解

信号可打断等待；非阻塞对象无可用资源时报告 EAGAIN/EWOULDBLOCK。写入 pipe/socket 等对象还涉及对端关闭和 SIGPIPE。一个 write 成功并不意味着远端业务处理或落盘持久化成功。

## 例子与推演

发送 N 字节：offset=0；每次写 remaining；n>0 推进；EINTR 受控重试；EAGAIN 等待可写且遵守总 deadline；其他错误终止。不能在 EAGAIN 时无限忙循环。

## 常见误区与失败边界

把 -1 强转 size_t 后加到 offset 会造成巨大越界。无视实际返回值，或者每次重试都从头写，会漏数据或重复数据。

## 面试追问

每次被信号打断都重置 timeout 有何问题？答：攻击或异常信号可让整体等待超过 deadline，应计算剩余时间。

## 动手练习与验收

用小容量 pipe/非阻塞 socketpair 制造短写和 EAGAIN。验收：完整数据正确、超时有限、不丢进度，真实板网卡未测试。
