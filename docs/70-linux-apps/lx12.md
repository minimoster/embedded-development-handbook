# LX12 · Linux GPIO/UART/SPI/I²C 应用应走什么接口？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

先使用对应子系统公开接口与受支持库/工具，再考虑新驱动。GPIO字符设备、串口termios、spidev/I²C设备接口各有自己的配置与权限合同，不能直接多线程读写裸硬件地址取代驱动。

## 原理拆解

内核负责资源、并发与设备状态，应用仍需交易互斥、超时和帧解析。一次系统调用的原子性不自动覆盖多步设备事务；多个进程同时访问也需要设备/应用层约束。接口可睡眠，普通Linux调度延迟需评估。

## 例子与推演

多个线程读取同一I²C设备寄存器，可把完整“设置寄存器地址+读数据”的事务交同一适配器接口/串行拥有者。串口接收依然是字节流，本手册解析器可与硬件adapter分离。

## 常见误区与失败边界

旧sysfs GPIO示例与新字符设备接口版本不同；本文不假设所有内核都开放相同节点。GPIO kernel consumer API与用户API也不能混为一个函数。

## 面试追问

如果已有接口不能完成设备时序怎么办？答：先查驱动/子系统能力和设备规范，再决定写驱动，不擅自映射MMIO。

## 动手练习与验收

列目标内核支持接口、节点权限与事务拥有者。验收：具体代码前读该接口官方文档，真实设备未运行明确标注。
