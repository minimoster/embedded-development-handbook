# LX03 · 阻塞、非阻塞、select/poll/epoll 如何建立模型？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

阻塞/非阻塞描述操作如何等待，I/O 多路复用描述一次等待多个 fd 的就绪。epoll 在 Linux 上维护关注集合与返回事件；就绪只是可以尝试 I/O，不代表业务帧完整或下一操作一定不会变化。

## 原理拆解

LT 在仍就绪时可再次通知；ET 通常只在状态变化时通知，常用非阻塞并读/写至 EAGAIN。返回事件后另一个线程可能消费资源，因此保持非阻塞防止意外挂住。应用还要处理关闭、错误和取消。

## 例子与推演

ET 读到100字节只处理20后退出，若不再有新的边沿，剩余数据可能停滞。常用非阻塞并最终处理到 EAGAIN；若一次处理预算提前用尽，要把该连接保留在用户态 ready 队列等本地可继续状态，轮转服务其他连接后继续处理，不能直接阻塞等待不存在的新边沿。资源与公平预算详见 [LX18](lx18.md)。

## 常见误区与失败边界

“epoll 永远 O(1) 所以一切更快”掩盖负载、就绪数量、内核工作与应用成本。EPOLLOUT 常就绪，持续关注会导致忙循环，应按待发数据管理。

## 面试追问

为何 LT 更容易写对？答：未消费完就绪仍可再被通知，但仍需非阻塞与公平预算，不是自动正确。

## 动手练习与验收

做 socketpair 事件循环，覆盖多帧、短读、关闭。验收：ET 不漏剩余数据，写关注只在需要时开启，loop 不忙等。
