# LX10 · timerfd 和绝对时刻周期任务怎么保证边界？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

timerfd把定时事件变成可等待读的fd，适合epoll事件循环；读到到期计数可知道错过多少次。绝对时刻等待可减少相对sleep累积漂移，但仍会受调度延迟，不能声称普通Linux天然硬实时。

## 原理拆解

选CLOCK_MONOTONIC等适用时钟并明确墙钟跳变影响。每轮按计划next推进，记录实际开始差值；错过多周期时选择丢旧/追赶/报告。clock_nanosleep的返回错误语义与一般syscall区分。

## 例子与推演

目标周期10ms，next=t0+10ms*n；若实际醒来在37ms，应按业务处理30ms迟到或跳到40ms，不盲目再sleep10ms导致永久漂移。timerfd读完整uint64_t计数而非随意字节数。

## 常见误区与失败边界

高精度时钟读数不等于高精度调度。“设SCHED_FIFO就实时”还要评估权限、饥饿和最坏延迟；不擅自改变系统调度安全配置。

## 面试追问

为什么睡眠1ms常超过1ms？答：唤醒就绪与实际得到CPU不同，还受粒度、负载和中断影响。

## 动手练习与验收

主机记录有限次数的计划/实际时刻并统计max。验收：报告环境，测试不是硬实时证明，错过周期策略确定。
