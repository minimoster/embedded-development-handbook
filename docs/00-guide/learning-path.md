# 从一条可验证的数据链开始

这套手册面向准备嵌入式实习、需要把语言/系统/硬件知识连起来的学习者。学习主线是“知道结论 → 解释机制 → 手推例子 → 运行测试 → 验证边界”，面试题是检查理解的工具。它不会替你制造项目经历，也不保证面试结果。

## 第一步：选主方向

- MCU / RTOS：先学 C、架构/启动、GPIO/时钟/定时器，再串 UART/ADC/DMA、FreeRTOS、可靠存储与恢复。
- Linux 应用：先学 C/C++、资源管理和构建，再学进程/线程、文件/网络 I/O、部署、故障诊断。
- Linux BSP / 驱动：在共享基础之后加入启动、设备树、字符设备、MMIO/DMA 和内核并发。用户空间 API 先于自创驱动。
- C++ 算法：独立练习题单，帮助训练容器、边界和复杂度；算法通过不能替代硬件/系统理解。

不要同时把三条主方向都当主线。先把一个小链路做完整，另一方向先能说明接口边界。

## 四阶段验收

### A · 修好语言与构建模型

读 C01–C22、ST01–ST07、AR01/AR02/AR06/AR09。能解释指针/长度、生命周期、const/volatile、UB、所有权与声明/定义。运行主机 C/C++ 测试，解释每个边界为什么需要测。

验收：两个源文件成功链接；能定位缺定义；能画每块内存的拥有者；帧解析器面对截断、超长和任意分片不越界；不要运行已知 UB 猜答案。

### B · 连起一条硬件/系统数据链

MCU 读 AR03/AR04/AR07、MC01–MC10、PR01–PR04。先轮询，再 IRQ，再 DMA；保存实际型号/库版本、时钟树、波形、buffer 所有权与错误计数。

Linux 读 LX01–LX18、PR05–PR13。先用主机模拟设备/socketpair，再交叉构建到目标；处理短读写、分帧、断连、背压和有限退出。

验收：每个输入可追踪到输出；能解释容量与时延来源；硬件未测就写“未测”，不用虚构结果补齐。

### C · 把主方向工程化

MCU 读 RT01–RT10，画任务/ISR优先级、同步和栈预算；Linux应用把重连、日志与部署纳入项目；BSP/驱动路线读 DV01–DV12、BT01–BT08，固定内核/板/构建版本。

验收：正常、满队列、超时、取消、重启五种场景可解释并可重放。ASan/UBSan只覆盖已执行主机路径，不是实时或板级证明。

### D · 用真实证据答辩

读 DB01–DB06、PJ01–PJ05。按目标、约束、架构、本人工作、故障、验证和取舍准备介绍。每个知识点练直接回答，再画例子/失败路径，最后提出一个能证伪假设的实验。

验收：2分钟项目说明无编造指标；随机8题能解释机制和边界；一项错误有日志/源码/图/波形证据；尚未完成内容明确列出。

## 从面经练异常与答辩

基础验收后进入[公开面经与故障场景](../120-interviews/README.md)。MCU/RTOS先练IC01/IC02，再练cache与OTA；Linux驱动练IC04/IC07。先读与岗位匹配的自报主题，再用官方依据解释异常，不背公司题库或虚构已做过的板测。

## 每次学习的40分钟模板

1. 5分钟：不看答案，用自己的话回答一题。
2. 10分钟：读机制，画对象/时序/数据流。
3. 15分钟：运行或手推例子，修改一个边界输入。
4. 5分钟：回答追问，记录“不确定”和验证方法。
5. 5分钟：写验收结果，隔天复述一次。

P0/P1/P2是课程依赖建议，不是招聘市场考频。P0先修；P1随主方向；P2按目标需求深入。每题用同一模板：直接回答、原理、例子、误区、追问、练习、来源。硬件或内核示意代码不冒充已经编译运行的工程。
