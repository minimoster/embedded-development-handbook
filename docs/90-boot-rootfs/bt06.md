# BT06 · initramfs、initrd、文件系统和 PID1 怎么区分？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

initramfs常为cpio内容由内核解包到早期rootfs，历史initrd涉及块镜像流程；不能只当两种压缩扩展名。PID1负责最初用户空间初始化，其退出/失败影响系统；最终存储文件系统按介质与需求选择。

## 原理拆解

启动可在早期用户空间加载/准备设备并切换根，或直接挂最终root。BusyBox可提供工具/简洁init，但配置决定功能。只读系统+独立持久数据可降低故障面，写缓存与断电耐久需单独验证。

## 例子与推演

恢复系统用小initramfs和必要工具，主系统另挂存储rootfs；串口救援能启动不代表最终服务配置正确。调试init路径、执行权限、解释器/动态加载器和架构。

## 常见误区与失败边界

“有/bin/sh就是完整rootfs”忽略库、设备、挂载与启动管理。文件系统类型不可脱离NOR/NAND/eMMC/只读/更新约束随意推荐。

## 面试追问

PID1为何特殊？答：初始用户空间与进程管理责任、退出语义不同，应用daemon不等于PID1。

## 动手练习与验收

做一份文件/内核配置/启动参数三方依赖表。验收：init路径可解释、最终根来源确定，真实启动与掉电测试未做标未验证。
