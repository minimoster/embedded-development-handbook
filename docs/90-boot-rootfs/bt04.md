# BT04 · OTA 的 A/B、回滚与掉电安全如何联动？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

可靠升级先写非活动槽，校验格式/真实性/适用版本，再原子切换启动选择；新版本经过健康确认后提交，否则回滚。关键元数据本身也要掉电安全，不能只给镜像做双份。

## 原理拆解

升级状态有下载中、已验证、试启动、已确认、回滚等；启动次数/超时防止无限启动坏镜像。签名验证和版本策略需信任根，CRC 不足以防攻击。存储空间、Flash 原子粒度和更新 bootloader 的风险单独分析。

## 例子与推演

A 正常→下载 B→验证 B→记录 pending B→重启试 B→采样/通信/存储健康达标→confirm B。掉电在任一步重启都能找到可信旧/新启动状态，测试应覆盖所有写步骤。

## 常见误区与失败边界

“应用能启动就确认”可能在网络/传感器未工作时过早提交。回滚允许旧版本时还需考虑安全与数据格式兼容，不能无限退至有漏洞版本。

## 面试追问

升级 rootfs 后旧程序不懂新数据格式怎么办？答：数据迁移要支持回滚，或把不可逆迁移放在明确提交后并有恢复策略。

## 动手练习与验收

做主机状态机掉电注入矩阵。验收：每个中断点能恢复，真实性/完整性/健康分开；生产安全方案需平台官方能力与审计。
