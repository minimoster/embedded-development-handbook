# BT01 · Boot ROM、SPL、U-Boot、kernel、init 的责任链？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

启动链依 SoC 和板级方案变化。Boot ROM 通常按芯片规定找下阶段；可选 SPL/TPL/VPL 处理受限早期初始化；U-Boot/其他 loader 加载内核、DTB 等；内核建立运行环境并启动用户空间 PID1。

## 原理拆解

早期 RAM、时钟、DDR 和存储可用性决定分阶段设计。不是所有板都用 SPL，也不是所有设备都用 U-Boot。每个阶段应知道当前执行者、镜像来源、内存、控制台和失败证据。

## 例子与推演

若有 SPL：片上 SRAM 里完成必要 DDR 初始化→加载 U-Boot proper→按配置加载 kernel+DTB→传 cmdline→内核挂根并执行 init。该图是选型示例，不是所有 ARM 设备定律。

## 常见误区与失败边界

STM32 复位 startup、PC BIOS 与 Linux SoC 引导不可混成一条固定流程。串口沉默可能发生在任何早期阶段，不能直接断言内核坏。

内核位于rootfs中的一个文件不意味着内核变成应用程序；bootloader仍需正确加载、必要时解压并满足架构入口契约。PC BIOS/GRUB流程与ARM32 SVC示例都不能泛化为所有SoC。bootm/booti具体语法及AArch64入口边界见 [BT08](bt08.md)。

## 面试追问

卡在 Starting kernel 怎么排？答：检查控制台/earlycon、DTB、镜像架构/地址、内存冲突和传参，再追内核日志。

## 动手练习与验收

画自己目标板的实际链，逐阶段列输入输出与恢复入口。验收：所有可选阶段标明可选，无未经硬件验证的地址。
