# BT02 · kernel image、DTB、initramfs 与 rootfs 的区别？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

kernel image 是内核代码；DTB 描述硬件；initramfs 是早期用户空间的文件集合，常可先运行 init 再切根；rootfs 是最终用户空间运行所需文件系统内容/载体。它们必须匹配板、内核和启动参数。

## 原理拆解

内核能运行不等于根文件系统可挂载。存储驱动、文件系统支持、root= 参数、分区识别和 PID1/动态加载器都可能阻断后续。initramfs 可用于恢复和早期解锁，但不是一律必需。

加载文件地址、解压/搬移地址与入口地址要分开记录。bootm的FIT配置/子镜像选择与booti的Image、initrd:size、FDT位置参数不能混成-d/-s选项。保存每个镜像的实际大小，不能把下一次load更新后的filesize当上一个initrd大小。

## 例子与推演

日志“VFS unable to mount root fs”先查 root 参数与驱动是否 built-in/可用；“No working init found”查 /sbin/init 或 /init、权限、架构和动态加载器，而不是先重刷全部 Flash。

## 常见误区与失败边界

rootfs 不等于 Linux 内核，也不只是随便几个目录。复制 x86 二进制到 ARM 根目录可能显示存在却无法执行。

## 面试追问

为什么文件存在却报 No such file？答：可能缺该 ELF 的解释器/动态加载器；用 readelf -l 查，不只 ls。

## 动手练习与验收

做启动故障决策树并附需收集的日志。验收：把挂载失败、init 不存在、ABI/loader 不匹配分开。
