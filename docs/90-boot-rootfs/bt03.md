# BT03 · Buildroot、BusyBox 与可复现系统如何搭建？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

Buildroot 从配置生成工具链、内核/boot 组件及 rootfs 等产物；BusyBox 把多种用户工具组合到较小程序中。它们不是完整发行版包管理器的同义词，定制依赖与升级策略需要工程化。

## 原理拆解

保留 defconfig、板级配置、package recipe、overlay、补丁和版本，可重建产物。手改 output/ 中生成文件会被后续构建覆盖，应该回到正式配置/包/overlay。license 信息与软件物料表也属于发布准备。

## 例子与推演

把自己的采集服务做成 Buildroot package，依赖与安装路径写在 recipe；默认配置由 overlay 或受控安装脚本提供。运行日志与实际镜像哈希关联，设备上临时改动要记录但不替代可复现输入。

## 常见误区与失败边界

“我压缩了一份 rootfs，所以可复现”缺工具链、配置、依赖版本与构建步骤。选择 latest 滚动源码也可能让明天产物变化。

## 面试追问

Buildroot 能在目标机器 apt install 吗？答：不能把它当默认提供 apt 的发行版，新增组件一般通过构建配置和重建镜像。

## 动手练习与验收

设计一个最小 package/overlay 目录和版本锁定清单。验收：新的干净构建可以得到预期文件，真实 QEMU/板启动未跑就标未验证。
