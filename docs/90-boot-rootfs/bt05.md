# BT05 · Flash 分区、环境变量与救砖如何规划？

学习优先级：P2。先独立回答，再展开机制与验证。

## 直接回答

分区要覆盖启动组件、系统槽、持久数据与恢复，结合介质的擦写/坏块/对齐限制。boot 环境变量能影响加载路径，需控制完整性和恢复；备份与恢复流程必须先验证再依赖。

## 原理拆解

不同 NOR/NAND/eMMC 文件系统与坏块策略不同，不把通用文件写入语义套所有介质。恢复入口可为 ROM boot、串口/USB、独立恢复镜像等，由平台提供。禁止使用未经确认地址的擦写命令教学。

## 例子与推演

在纸面分区图标出哪个阶段读取、哪个升级器写入、失效后如何恢复。重要配置和校准数据与系统槽分开，恢复不得无意擦除。镜像版本和板版本要匹配。

## 常见误区与失败边界

“重刷一定能救”忽略 boot 配置、信任根、介质和校准数据。错误 erase 地址有不可恢复风险，本文不提供直接执行命令。

## 面试追问

如何降低更新 bootloader 风险？答：减少更新频率、可靠备份/恢复路径、原子策略和专门测试，必要时用户接手硬件恢复。

## 动手练习与验收

制定只读备份/版本核对清单及恢复演练方案。验收：数据保留范围与每步风险明确，实板救砖未做不声称。
