# 48. 旋转图像（C++17）

> 矩阵 · MEDIUM。前置：能读懂本题使用的容器与递归/循环状态。建议先手推，再自己写，最后看实现。

## 题意与接口边界

将n×n方阵顺时针旋转90度，必须原地修改。矩形非方阵不是此接口的合法输入。

题目与完整输入约束：[官方题页](https://leetcode.cn/problems/rotate-image/)。本页为原创教学表达，不重复完整官方题面。

## 从朴素思路走向主解

坐标映射是(i,j)→(j,n-1-i)。拆成两次容易原地执行的变换：转置让(i,j)→(j,i)，再反转每行把列i变成n-1-i。这个代数拆分比逐层四点轮换更容易检查。

## 状态与执行步骤

只枚举主对角线上方的(i,j)并交换matrix[i][j]与matrix[j][i]完成转置；再逐行reverse。主对角线不动，每对对称项只交换一次。

## 手推一组自建例子

[[1,2],[3,4]]转置为[[1,3],[2,4]]，逐行反转为[[3,1],[4,2]]。原左下的3移到左上，符合顺时针旋转；连续4次旋转应还原。

读到这里先暂停：不看代码，画出每次选择/指针移动后的状态；必须能解释为什么这一步安全，才算理解。

## 为什么正确

转置与行反转复合后，原(i,j)先到(j,i)，再到(j,n-1-i)，恰是目标映射。两个操作都是双射，不丢值不复制值；全部位置都被映射一次。

## 完整 C++17 实现

源码：[可编译头文件](../../../algorithms/cpp/solutions/p0048_rotate_image.hpp)。本地包装的namespace用于把100题同时编译；在线平台提交时只保留类及所需标准头，链表/树节点以平台提供定义为准。

```cpp
#pragma once
#include "../support.hpp"

namespace hot100::p0048 {
class Solution {
public:
    void rotate(std::vector<std::vector<int>>& matrix) {
        const int n = static_cast<int>(matrix.size());
        for (int i = 0; i < n; ++i)
            for (int j = i + 1; j < n; ++j) std::swap(matrix[i][j], matrix[j][i]);
        for (auto& row : matrix) std::reverse(row.begin(), row.end());
    }
};
} // namespace hot100::p0048
```

## 复杂度与存储边界

时间 O(n²)，额外空间 O(1)。转置约n(n-1)/2次交换，行反转也是O(n²)；没有新建矩阵。

## C++与边界陷阱

转置若循环遍历全部i,j，每对会换两次，最终抵消。反转每列而非每行会变成逆时针旋转。真实通用矩阵接口需要校验每行长度，本练习遵循官方方阵契约。

## 面试追问：先说变化，再改算法

逐层四点轮换同样常数空间，适合讲缓存访问与写入次数差异。若图像是连续RGB字节缓冲，旋转像素与旋转单字节不是同一件事，还需考虑步幅与像素布局。
