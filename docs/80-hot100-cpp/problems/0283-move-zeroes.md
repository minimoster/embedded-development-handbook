# 283. 移动零（C++17）

> 双指针 · EASY。前置：能读懂本题使用的容器与递归/循环状态。建议先手推，再自己写，最后看实现。

## 题意与接口边界

原地把0移到末尾，所有非零数的相对顺序保持不变。这里要求稳定，不只是最终把0集中起来。

题目与完整输入约束：[官方题页](https://leetcode.cn/problems/move-zeroes/)。本页为原创教学表达，不重复完整官方题面。

## 从朴素思路走向主解

反复删除再追加会挪动大量元素。把数组分成已安置非零段、已处理零段、未处理段，read负责看新数，write指出下一个非零该放的位置。

## 状态与执行步骤

read从左到右前进。遇0不动作；遇非零就与write交换，再推进write。read==write时略过自交换。扫描结束时，非零都在前缀，后缀自然全0。

## 手推一组自建例子

[0,4,0,-2,7,0]：read=1将4换到0；read=3将-2换到1；read=4将7换到2。前缀变[4,-2,7]，后缀是三个0，原非零顺序未改变。

读到这里先暂停：不看代码，画出每次选择/指针移动后的状态；必须能解释为什么这一步安全，才算理解。

## 为什么正确

循环开始时[0,write)是原已读元素中的全部非零，且顺序不变；[write,read)全为0。新读到非零时，与零段首交换正好延长稳定前缀；新读到0时只延长零段。

## 完整 C++17 实现

源码：[可编译头文件](../../../algorithms/cpp/solutions/p0283_move_zeroes.hpp)。本地包装的namespace用于把100题同时编译；在线平台提交时只保留类及所需标准头，链表/树节点以平台提供定义为准。

```cpp
#pragma once
#include "../support.hpp"

namespace hot100::p0283 {
class Solution {
public:
    void moveZeroes(std::vector<int>& nums) {
        std::size_t write = 0;
        for (std::size_t read = 0; read < nums.size(); ++read) {
            if (nums[read] != 0) {
                if (write != read) std::swap(nums[write], nums[read]);
                ++write;
            }
        }
    }
};
} // namespace hot100::p0283
```

## 复杂度与存储边界

时间 O(n)，额外空间 O(1)，输入就地修改。实现至多做一次扫描，且只在非零需要搬移时交换。

## C++与边界陷阱

不能拿尾部非零换前部零的相向双指针写法，那会打乱顺序。size_t不会为负，这题无需 read--，用它安全；涉及倒序时不要照搬无符号类型。交换版本写入两次，写指针覆盖再补零是另一种可解释的权衡。

## 面试追问：先说变化，再改算法

若Flash写入成本高，如何减少无变化写？可以只写值发生改变的位置。若要稳定地把满足任意谓词的元素挪到末尾，先讨论原地稳定分区通常比本题难。
