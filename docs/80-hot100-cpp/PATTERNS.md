# 从100题练到能解释、能写、能迁移

## 四轮学习，而不是一遍看完

1. 第一轮读契约和自建例子，先写朴素解：它往往是后续随机对拍的独立oracle。把“不改输入/必须改输入”“是否互异”“值域/结果范围”写在草稿开头。
2. 第二轮找状态：窗口合法性、前缀频次、单调候选、链表边界、树返回值、搜索选择/撤销、DP含义。先解释不变式，再写代码。
3. 第三轮闭卷实现并运行本题测试，新增一个自己设计的反例。失败先分类：契约误读、状态污染、越界、去重、溢出、复杂度超限，不要盲目改模板。
4. 第四轮做题尾追问：变化的是输入前提、输出目标、内存约束还是数据到达方式？只有能说清变化为什么打破旧证明，才适合改算法。

## 嵌入式岗位的C++检查清单

- 数值：`size_t`倒序是否下溢？int加减乘在表达式发生前是否已经提升？返回类型是否仍受约束？
- 生命周期：ListNode/TreeNode由谁分配回收？借用指针是否指向仍活着对象？是否把测试arena节点误delete？
- 容器：vector扩容使哪些引用失效？unordered_map重哈希会使哪些迭代器失效？list.splice为什么适合LRU？
- 内存预算：输出大小、按值参数副本、递归栈深、容器节点开销和最坏待处理队列大小分别是多少？在线题的O(1)辅助空间不等于零内存。
- 实时性：哈希均摊和随机选择期望界不等于硬实时最坏时延；若用于实时系统，应选有界存储、输入上界与确定性复杂度。
- 可复用性：同一实例调用两次是否污染？函数改写输入是否有说明？搜索成功提前返回是否恢复临时状态？

## 一次20分钟口述练习

用2分钟复述契约，3分钟给朴素解，5分钟讲主解与不变式，5分钟手推带边界的小例子，3分钟列复杂度与C++风险，2分钟回答一个题尾追问。不能证明的贪心、无法定义的DP状态，优先回到概念，不急着刷下一题。
