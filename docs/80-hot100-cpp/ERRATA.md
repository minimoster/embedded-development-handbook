# 算法实现的复用与边界提醒

在线判题的对象生命周期与工程复用方式可能不同。先明确输入范围、修改行为与所有权，再检查以下风险。

## 状态与生命周期

- 搜索结果、访问标记、游标和最优值宜局部化；若使用成员状态，每次调用都应重新初始化。连续调用测试能揭示旧状态残留。
- 哑节点、复制链表、Trie和缓存节点都需要回收者。RAII能简化生命周期；借用的测试arena节点不能由算法随意delete。
- 递归搜索、树遍历和逐节点合并必须计入调用栈，显式stack同样消耗空间。

## 复杂度与平台

- 哈希操作区分平均、均摊和最坏模型；不能把哈希表当作硬实时常数保证。
- set去重增加树操作成本；堆选择与随机quickselect的复杂度不同，后者还需记录最坏O(n²)。
- 搜索树深度取决于输入与target；输出复制、排序、递归栈都应计入。
- long不保证64位，数值中间值、极值哨兵、迭代器与空输入均需明确边界。

## 区间和输入契约

- 单词拆分dp[i]表示半开前缀s[0,i)，长度为i；dp[0]与dp[n]必须对应同一状态定义。
- 固定尺寸网格、正候选限制、非空树与合法k都属于输入契约。扩展接口时新增验证和回归测试，不能以契约外行为判断原题算法。
- 给每次修正补一个能区分旧、新行为的测试，避免只改注释。题号、公开链接与学习入口见[题单清单](manifest.json)。
