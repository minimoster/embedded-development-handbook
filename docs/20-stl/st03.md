# ST03 · map、unordered_map 与哈希退化怎么回答？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

有序映射支持键的排序与范围查询；unordered_map 通常提供平均常数复杂度查找，但最坏情况可能线性。选择时还需考虑分配次数、内存开销、哈希安全、键大小和实时预算。

## 原理拆解

哈希将键映射到 bucket，再用等价关系区分碰撞。hash 与 equality 必须一致：等价键必须给出同样 hash。load factor 和 rehash 影响空间与突发时延，不能把平均复杂度当硬实时上界。

## 例子与推演

设备 ID 是 0..255 且稠密，数组可能比树/哈希更简单；字符串配置名且需按字典序输出，可考虑 map。收到不可信网络键时，要评估可控碰撞和长度造成的 CPU 消耗。

## 常见误区与失败边界

不能承诺标准 unordered_map 一定使用某种碰撞结构。以浮点近似相等为键等价关系若不具传递性，可能违反关联容器所需合同。

C++标准规定有序/无序关联的语义和复杂度，并不强制std::map/std::set使用红黑树。set/map也不会因都能按键查询就变成哈希结构。红黑树插删、缓存局部性、节点分配和小数据集的实际取舍需按负载测量，不从结构名字推绝对最快。

## 面试追问

怎么让查找有可证明上界？答：有限键空间用数组，或固定容量、明确探测上界的表，并设计满表失败。

## 动手练习与验收

比较小固定键集合的数组、map、unordered_map，不只报告一次耗时。验收：同时报告容量、分配、最坏路径与查询语义。
