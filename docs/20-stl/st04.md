# ST04 · string、string_view 与二进制数据有哪些坑？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

string 拥有字节；string_view 只引用已有存储，不负责延长生命期，也不保证末尾有零。二进制缓冲区要显式长度，不能由 strlen 推导。

## 原理拆解

从临时 string 返回 view 会悬空；原 string 重分配也可能让 view 失效。c_str 适合需要零结尾的 C API，但 string 内部允许嵌入零。view.data() 不代表可传给只认零结尾的 API。

## 例子与推演

```cpp
#include <string>
#include <string_view>
std::string bytes("A\0B", 3);
std::string_view v(bytes.data(), bytes.size());
/* v.size()==3；strlen(bytes.c_str()) 只得到 1。 */
```
解析函数返回 offset/length 或由调用方持有原存储，避免隐藏生命周期。

## 常见误区与失败边界

string_view 不是小型 string 的自动安全替代。将接收帧强转成 char* 打日志会越界或泄露后续内存。小字符串优化属于实现细节，别当固定容量保证。

## 面试追问

零拷贝解析何时更危险？答：当缓存会复用、DMA 重写、异步消费者晚于存储释放时。

## 动手练习与验收

解析含零、空串、无终止符的缓冲区；验收：所有读操作都用长度边界，并标注 view 的拥有者。
