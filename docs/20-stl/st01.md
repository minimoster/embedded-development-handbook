# ST01 · vector、array、list 的选择依据是什么？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

先看容量上界、访问模式、实时约束和失效规则。array 固定容量、连续存储；vector 连续且可增长；list 节点分散，稳定节点访问不能抵消分配与 cache 成本。不要只凭“插入 O(1)”选 list。

## 原理拆解

vector 中间插入要移动后续元素，扩容可能重新分配；reserve 提前安排容量，却不能保证超过 capacity 后仍不分配。list 在已有迭代器位置插入复杂度低，但找到位置仍需要遍历。

## 例子与推演

采样缓冲最多 128 点，array 加有效长度可避免增长；后台批处理可以 vector 并 reserve。若使用 vector 的 data() 交给 DMA，在 DMA 完成前禁止使存储重分配或结束生命周期。

## 常见误区与失败边界

reserve 不增加 size，v.reserve(10) 后直接写 v[9] 仍越界。DMA buffer 的地址稳定还不够，需满足内存区域、对齐、cache 和外设可达性。

## 面试追问

为什么 list 二分查找不再有随机访问的优势？答：推进迭代器需要线性工作，比较次数与实际步进成本不同。

## 动手练习与验收

用 vector 的 size/capacity 打印增长，并用边界检查访问。验收：解释 reserve/resize，给实时路径选择一个有可验证上界的容器。
