# ST02 · 迭代器失效为什么比复杂度更容易出 bug？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

容器修改可能使原有迭代器、指针或引用失效。规则因容器与具体操作而异；失效对象不能继续解引用。不要将某次分配地址未变化作为接口保证。

## 原理拆解

vector 扩容会使所有元素地址相关视图失效；不扩容的插入/删除也可能使受影响位置之后的视图失效。erase 常返回后继有效迭代器，应使用返回值继续循环。范围 for 内直接 erase 会破坏隐含迭代器。

## 例子与推演

```cpp
#include <vector>
std::vector<int> v{1,2,3,4};
for (auto it=v.begin(); it!=v.end();) {
    if (*it%2==0) it=v.erase(it);
    else ++it;
}
```
每次删除后不再使用原来的 it。

## 常见误区与失败边界

“引用永远比指针安全”错误，它也可能悬空。对 unordered_map 的 rehash 和 erase，要查精确规则，不要把 vector 的规则类推过去。

## 面试追问

读取线程拿 vector 元素引用，写线程 push_back，安全吗？答：还存在竞争与可能重分配，需要同步和生命期合同。

## 动手练习与验收

实现删除偶数、空容器和全删除测试；验收：不跳过相邻匹配元素，不缓存失效 end，也不解引用 erase 前的迭代器。
