# ST07 · deque、stack、queue 和 priority_queue 应按什么合同选择？

学习优先级：P1。语言基线：C++17；配合 ST01、ST02、ST05、ST06。

## 直接回答

deque提供双端插入删除与随机访问，却不保证元素连续；stack/queue/priority_queue通过底层容器限制接口并维持特定顺序。stack默认deque，也可用vector；queue要求pop_front等操作，vector不满足接口而非“容量有限”。priority_queue维护堆，默认最大元素在顶，不是完整排序数组。选择需同时考虑访问语义、地址/迭代器失效、分配与容量上界。

## 原理拆解

deque随机访问不等于data()连续缓冲，不能把它直接提交给需要整段连续地址的DMA或外部协议接口。标准规定两端插入的复杂度，但实现可能仍有分配与缓冲管理；“常数复杂度”不是无分配/恒定机器周期承诺。常见分段结构可用于解释实现，不背成每家库必须有同一个中控器。

deque两端插入会使迭代器失效，但已有元素引用保持有效；中间插入会使元素引用与迭代器失效。删除与past-the-end有具体规则，必须按实际操作查条款，不能认为两端操作永远保住旧end。访问还要受并发和生存期合同约束。

stack底层要提供back/push_back/pop_back，vector符合。queue底层要提供front/back/push_back/pop_front，deque/list符合而vector没有pop_front。默认底层均为deque；改变底层也改变分配、复杂度和失效特征，适配器并未抹去这些成本。

priority_queue默认vector和less：top是按照less的序关系处于最后的元素，即通常最大值。用greater可得到通常最小值在顶。push/pop维护堆关系，top为常数访问，插入/删除具有对数级比较操作；vector扩容、元素移动和分配成本仍须计算。比较器要满足严格弱序，不能捕获不断变化的外部优先级值。

## 例子与推演

```cpp
#include <functional>
#include <queue>
#include <vector>
std::priority_queue<int> largest;
std::priority_queue<int, std::vector<int>, std::greater<int>> smallest;
```

把3、1、3、2放入两者，largest.top()为3，smallest.top()为1；重复pop后得到相应顺序。只看top不会自动给出底层全序，也不能在pop后继续使用先前top的引用。访问top/pop之前必须确认非空。

设计“最多32条待发控制命令”时，先决定FIFO、LIFO还是按优先级，再给出满容量失败行为。std::queue本身不是天然固定容量消息队列；硬实时路径可选预分配的固定环形容器及显式背压。含unique_ptr的容器可以通过移动接收拥有者，但queue.front的借用生命期和pop释放责任要单独规定。

## 常见误区与失败边界

- deque不是一个可整体提交给DMA的连续vector
- stack可以用vector，不能以“不能扩容”解释排除
- queue是容器适配器，不等同FreeRTOS可阻塞的队列，也不自带锁
- priority_queue默认大堆；自定义比较器不能写<=或依赖实时读取变化寄存器
- 摊还/渐进复杂度不能直接推出硬实时最坏执行时间
- 有地址稳定保证仍不代表无需并发同步或cache维护

## 面试追问

为什么不能从默认priority_queue任意删一个中间任务？答：适配器没提供该接口；可设计取消标志+惰性移除、索引堆或其他有明确更新合同的数据结构，同时限制残留项上界。

如何避免紧急任务淹没普通任务？答：堆只决定取出顺序，公平性、超时、配额和背压属于调度/业务策略。
