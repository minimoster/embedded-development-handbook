# PR08 · TCP/UDP、超时重试和幂等怎样一起选？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

TCP 提供字节流的交付/排序机制；UDP 保留数据报边界，但无连接层的可靠排序保证。业务仍需设计 deadline、重试与幂等，TCP 可靠不等于控制命令一定只执行一次。

## 原理拆解

请求已到服务器执行但响应丢失，客户端重试可能重复操作。可为命令提供 operation ID，服务器记录结果或基于状态版本执行。UDP 上若自建 ACK/窗口/重传，要评估复杂度和拥塞行为，不轻率复刻 TCP。

## 例子与推演

“设置目标温度=25”通常可天然幂等，“转动电机再前进10步”不是。把绝对目标/序号放协议中，比无限重发相对动作更可控；过期命令应拒绝。

## 常见误区与失败边界

“UDP 快，所以实时控制必选 UDP”忽略网络拥塞、乱序和业务安全。重试要有上限、退避、总 deadline 和观测，不能无界循环。

拔网线后 TCP 状态不一定马上断开；重传或可选 keepalive 可能最终发现失联，但不会自行新建一条连接。应用需设计重连、会话恢复和请求去重。20字节是 TCP 无选项最小首部；UDP 应用也要有负载与拥塞友好边界，不能把“无内建拥塞控制”理解为无限发送许可。

## 面试追问

如何证明只执行一次？答：网络中通常依靠应用去重与持久状态约束描述语义，不能只靠客户端没收到就再发。

## 动手练习与验收

模拟请求成功响应丢失、重复、乱序和迟到。验收：定义幂等/去重窗口、超时上界与过期处理，错误不会重复危险动作。
