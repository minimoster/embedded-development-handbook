# PR03 · RS485 和 Modbus RTU 不是同一层东西？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

RS485 主要定义差分电气传输，Modbus RTU 是常用于其上的协议。半双工 485 需要管理发送使能、总线占用和终端/偏置；RTU 还需要地址、功能、帧间隔与 CRC 等协议规则。

## 原理拆解

发送方向释放应在最后停止位真正发完后，而非仅内存 DMA 搬完。终端通常按总线拓扑末端安排，偏置与共模/隔离依板级设计。RTU 的时间判帧规则必须按波特率与规范，不把一次串口中断当帧。

## 例子与推演

控制 DE→启动发送→DMA 完成只表示 buffer 搬完→等待 UART TC→按设备时序释放 DE。超时应恢复接收并记录错误，避免一直占总线。

按Serial Line V1.02的RTU规则做一个时间预算：8个数据位、1个起始位、校验位和1个停止位共11bit（无校验时使用2个停止位，同样11bit）。9600baud时一个字符约1.146ms，t1.5约1.719ms，t3.5约4.010ms。低速按字符时间实施；高于19200baud时规范推荐固定t1.5=750μs、t3.5=1.750ms。超出t1.5的帧内间隔会使不完整帧被丢弃，至少t3.5的静默区间用于帧间分隔；这些阈值不等于响应超时。

地址0用于写广播且没有响应，主站不能等广播回复；单播请求另设响应超时。CRC发送时低字节先、高字节后，不要套用其他协议的字节序。计时精度、UART配置与收发器方向延时需由目标实现验证；这里没有串口或总线实测。

## 常见误区与失败边界

“RS485 自带地址/CRC”错误。串口多个设备连到一起不等于解决冲突，主站/请求响应时序需要协议。固定UART帧格式后再算字符时间；改变baud、校验或停止位时必须重新核对规范。

## 面试追问

两节点正常，多节点不稳怎么定位？答：先电气拓扑/终端/地与方向，再帧间隔/地址冲突与重试。

## 动手练习与验收

设计半双工状态机，注入 DMA 完成但线路忙、响应超时。验收：任何错误路径都释放总线，不把物理层和协议层混讲。

## 来源与适用范围

- [C11 委员会草案 N1570（2011）](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：公开草案，作为 C11 基线；不是最新版 C 标准。
- [ST AN4776：通用定时器](https://www.st.com/resource/en/application_note/an4776-generalpurpose-timer-cookbook-for-stm32-microcontrollers-stmicroelectronics.pdf)：STM32 定时器入门；具体功能以所选芯片 RM 为准。

- [Modbus Organization：规范入口](https://www.modbus.org/modbus-specifications)：官方列 Serial Line V1.02 与应用协议；具体文档许可/访问按原站。

- [Modbus Serial Line V1.02](https://www.modbus.org/file/secure/modbusoverserial.pdf)：2006规范，§2.1/2.5.1核对广播、RTU时序与CRC发送顺序。
