# PR06 · TCP 为什么会半包和粘包，怎样正确接收？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

TCP 提供可靠有序字节流，不保留应用 write/send 的消息边界。一次 read/recv 可读到部分消息、多条消息或任意中间段，应用必须自己定义帧。所谓粘包/半包是消息解析问题。

## 原理拆解

发送分段、网络路径、接收缓冲和调度都会改变每次读取长度。read 返回 0 对 stream socket 通常表示对端有序关闭；负值和 EAGAIN/EINTR 应分别处理。解析状态跨多次调用保留。

## 例子与推演

采用固定 4 字节大端长度+payload，先累计头，拒绝超过 MAX，再累计 body；可在同一 buffer 循环解析多帧，未完整部分保留。长度加头时先防溢出，不能先分配攻击者指定大小。

## 常见误区与失败边界

用“延迟 10 ms 后再读一次”解决粘包不可靠。MSG_WAITALL 也不能替代错误、关闭、超时和帧上限处理。

## 面试追问

关闭前发送成功就代表业务成功吗？答：send 可能只进入本机缓存，业务确认需应用响应与幂等策略。

## 动手练习与验收

对一个合法字节流枚举所有单次切分点，并用随机分片重放。验收：输出相同，截断/超长/连接关闭无越界和无限等待。
