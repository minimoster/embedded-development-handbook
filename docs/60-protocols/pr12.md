# PR12 · TCP 流量控制与拥塞控制有什么不同？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

流量控制保护接收端能力，拥塞控制适应网络承载能力。发送窗口受接收窗口和拥塞状态等限制；应用有界输出队列仍需背压，TCP不会自动限制所有应用内存积压。

## 原理拆解

接收端持续不读取会使接收窗口收缩；网络丢包/时延可改变发送进度。可靠重传不能保证某消息在deadline前到达，因此控制系统需过期策略。具体拥塞算法依协议/实现，不能一律说固定四阶段一种算法。

## 例子与推演

采样生产者不停向应用send队列加数据，网络慢时内核send也可能EAGAIN，应用队列若无上限就耗尽内存。按业务降采样/丢旧/暂停产生并统计队列年龄。

## 常见误区与失败边界

“TCP可靠所以无丢数据”忽略应用主动丢弃、断连和deadline。“窗口大就延迟低”也不成立，积压可加长延迟。

## 面试追问

接收窗口非零却发不快为何？答：还看网络拥塞、RTT、发送buffer、应用供给与调度。

## 动手练习与验收

模拟慢消费者及有限发送buffer。验收：同时记录queue depth/age，超时不会无限缓存旧控制命令。
