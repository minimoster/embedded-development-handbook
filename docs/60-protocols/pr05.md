# PR05 · OSI/TCP-IP 分层对嵌入式排障有何用？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

分层用于划清责任：物理/链路关心传输媒介和局域交付，IP 负责网络层寻址与路由，TCP/UDP 是传输层，业务帧在应用层。OSI 七层是参考模型，不能机械要求每个实现独立七段代码。

## 原理拆解

同样的业务超时可来自链路断开、地址/网关、DNS、TCP 连接、TLS 或服务器响应。按层验证能避免看 HTTP 错误就先改 PHY。协议封装会占 MTU，碎片和缓存限制对资源紧张设备特别重要。

## 例子与推演

设备连 Wi-Fi 但请求失败：先确认链路→IP/掩码/网关→DNS→目的端口连接→TLS→应用状态码。每步使用明确证据；ping 成功不保证目标 TCP 端口或业务可用。

## 常见误区与失败边界

“HTTPS 三次握手”把 TCP 建连与 TLS 握手混淆。某协议跑在 TCP 上不代表边界由 TCP 保留。

## 面试追问

如何区分 DNS 失败和服务连接失败？答：分别记录解析结果/时延与连接 errno/超时，不能只统一打印 network error。

## 动手练习与验收

为一次遥测请求画封装与失败点。验收：每层有一个可观测指标，所有超时能定位阶段。

## 来源与适用范围

- [IETF RFC 9293：TCP](https://www.rfc-editor.org/rfc/rfc9293.html)：2022 Internet Standard；TCP 是字节流。
- [IETF RFC 768：UDP](https://www.rfc-editor.org/rfc/rfc768.html)：UDP 保留数据报边界，但不提供 TCP 的交付保证。
