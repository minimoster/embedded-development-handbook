# PR04 · CAN 仲裁、标识符和错误处理怎样建立主线？

学习优先级：P2。先独立回答，再展开机制与验证。

## 直接回答

CAN 的标识符参与总线仲裁并描述消息，而不是天然等于节点地址。经典 CAN 与 CAN FD 的数据长度、位时序和控制格式不同，必须确定协议与控制器模式后讨论。

## 原理拆解

显性/隐性位使仲裁可不破坏获胜帧；输掉仲裁的节点等待后续发送。收发错误与错误计数可能导致 error-active/passive/bus-off 等状态，应用需设计恢复与报警。ID 优先级还影响低优先级消息延迟。

## 例子与推演

控制消息高优先级、诊断低优先级；如果高优先级持续占满总线，诊断可能饥饿。验证时记录总线负载、重传与错误帧，不只看“能收到”。本页不提供未核对的寄存器与位时序值。

## 常见误区与失败边界

把总线 ACK 当特定业务节点已处理消息错误。终端、波特率、采样点和收发器电气同样重要。CAN FD 配置不能套经典 CAN 固定长度说法。

## 面试追问

为何发 CAN 时一直重发？答：可能无其他节点 ACK、位时序/终端错误或物理故障，先检查控制器状态和波形。

## 动手练习与验收

以所选器件和协议官方规格补充位时序计算，画仲裁例子。验收：明确 classic/FD 与芯片；CiA 官方资料已核对概念；设备寄存器/位时序仍需具体控制器手册。
