# PR07 · TCP 建连、关闭和 TIME_WAIT 怎么讲？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

TCP 通过 SYN/SYN-ACK/ACK 同步连接状态，关闭则是两个方向分别结束发送，可能经历不同状态路径。TIME_WAIT 用于让旧报文在网络中消退并支持最后确认相关处理，不能简单当内存泄漏。

## 原理拆解

半关闭允许一方不再发送但仍接收。主动关闭方通常进入 TIME_WAIT，但同时关闭等路径需按状态机讨论。设备频繁短连接会带来连接状态与端口资源成本，keep-alive 或连接复用需匹配服务器与故障策略。

## 例子与推演

采集设备每 100 ms 建一次连接会放大握手与状态成本；复用连接可节省，但必须处理 idle timeout、断网、半开和重新认证。抓包用序号/ACK/FIN/RST 验证，不只数报文。

序号按字节空间推进：若 SYN 的 ISN 为1000，首个普通数据字节通常从1001开始；连续发20字节后，对端累计 ACK 可为1021。SYN/FIN 各占一个序号，纯 ACK 不占数据序号。RST 是重置/拒绝路径，不是协议自动要求重连。

## 常见误区与失败边界

“关闭永远四包”忽略 ACK/FIN 合并等实际报文情况。SO_REUSEADDR 不意味着可以忽略连接状态和安全复用规则。

## 面试追问

RST 与 FIN 有什么区别？答：FIN 表达有序关闭发送方向，RST 可立即终止/拒绝连接，应用错误语义要分别处理。

## 动手练习与验收

画主动、被动和同时关闭状态图，对照一次抓包。验收：说明哪方何时不能再发送、何时仍可接收，TIME_WAIT 不是随意删除的对象。
