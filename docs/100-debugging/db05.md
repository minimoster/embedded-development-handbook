# DB05 · 故障注入、背压和恢复为何比正常 Demo 重要？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

正常数据通路只是最低要求。必须主动注入超时、满队列、断连、坏帧、内存不足与掉电，证明系统退化与恢复可控。恢复动作应有次数/时间上限、统计和明确终态。

## 原理拆解

生产速率超过消费速率时队列迟早满；加容量只延迟问题。选择阻塞、丢新、丢旧、降采样或负反馈依业务。重试可形成放大/风暴，退避与总 deadline 能控制负载。

## 例子与推演

采样 1 kHz、网络仅 500 Hz，缓存 100 条约只能吸收 0.2 s 的持续净积压；需要减少速率、压缩/批量或有明确丢弃策略，不能假装100条足够永远运行。

## 常见误区与失败边界

只统计平均速率忽略突发。错误一出现就重启会掩盖根因；恢复过程中还要防旧数据重复提交与资源泄漏。

## 面试追问

发生10次失败后系统应怎样？答：定义停止/降级/报警/重连终态，不任意无界重试。

## 动手练习与验收

为每条通路列正常、饱和、断开、恢复四种状态。验收：容量与时间预算有计算，异常不造成无限内存增长或重复危险命令。
