# DB01 · HardFault 怎么从寄存器走到源码？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

先保留故障时上下文和故障状态，再用同一构建的 ELF、符号及反汇编定位。Cortex-M4 的 CFSR/HFSR 等可提供类别线索；堆栈中的 PC 不总是根因，错误可能在较早时发生。

## 原理拆解

异常入栈规则、MSP/PSP、浮点扩展帧和 EXC_RETURN 影响读取位置。BFAR/MMFAR 只有对应有效位说明时才解释地址。栈已损坏或 imprecise fault 时不能盲信一次 PC，需找此前内存错误。

## 例子与推演

记录构建 ID、PC/LR/xPSR、所用栈、CFSR/HFSR 和可用地址；addr2line/objdump 对应同一 ELF。对齐错误、非法函数指针、栈溢出分别提出可证伪实验。

## 常见误区与失败边界

只输出 HardFault 然后复位，丢失最有价值证据。把 Cortex-M4 的全部寄存器与帧布局套给 M0/M0+ 错误。

## 面试追问

故障只在 release 出现怎么办？答：先排 UB、竞态和时序，保留优化构建符号，不靠禁优化永久掩盖。

## 动手练习与验收

用虚构寄存器转储练定位，标注有效位与假设。验收：所有符号来自同一二进制，能说明未知部分；本仓库未执行硬件故障。
