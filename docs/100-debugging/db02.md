# DB02 · GDB、SWD/JTAG、断点与观察点怎么用？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

调试探针提供目标连接，OpenOCD 等连接 GDB 与目标；ELF 的符号把地址映到源码。断点停在代码位置，观察点监控数据访问，但硬件数量、访问宽度与可观察范围受目标限制。

## 原理拆解

软件断点修改指令，Flash 与只读区域可能受限制；硬件断点有数量上限。停机影响时序、看门狗、外设和并发，调试结果要与正常运行复验。观察点可能抓到 CPU 访问，却不一定能捕获所有 DMA 写。

## 例子与推演

追踪 buffer 被谁修改：先 watch 关键索引/哨兵，检查命中上下文；如果 DMA 写不触发，转到缓冲区所有权、DMA 地址、波形或 trace。attach 不复位与 reset-halt 有不同系统状态。

## 常见误区与失败边界

“单步没问题所以并发正确”错误。优化代码的变量可能被消除，源码行与指令不是一一对应。

## 面试追问

无法连接先排什么？答：供电、线序、接口模式、目标配置、复位、时钟与安全锁；不绕过安全限制。

## 动手练习与验收

主机 GDB 练 bt、frame、x 和 disassemble；板测另记录探针与目标。验收：说明硬件断点/停机副作用，不虚称实板连接已成功。
