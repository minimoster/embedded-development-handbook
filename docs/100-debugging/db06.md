# DB06 · 版本、CI、勘误与公开项目该保存什么？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

可复现工程保存源版本、工具链、配置、依赖、测试、产物哈希和已知限制。公开仓库只放获准再发布的原创内容/依赖，不放密钥、真实日志隐私、未授权第三方正文或保密硬件资料。

## 原理拆解

自动检查把静态格式、编译、主机测试与内容链接串起来，但不应命名为“已验证所有硬件”。datasheet、reference manual、errata 分工不同，某芯片行为要同时检查勘误。修订知识应留记录与适用版本。

## 例子与推演

一次 release 保存 git commit、编译器版本、board config、ELF/map、测试报告和外设版本。旧 ELF 与新 crash 地址混用会错误定位，公开日志前使用虚构 ID 和删敏感字段。

## 常见误区与失败边界

“最新依赖”降低复现性；将厂商示例无视许可证复制进仓库可能侵权。禁止收录来源广告、群二维码和下载 token。

## 面试追问

怎么证明你做过测试？答：提交可运行脚本、具体 case、原始结果与限制；截图只作辅助，不编造测量值。
