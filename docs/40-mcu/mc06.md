# MC06 · Cortex-M7 DMA 与 cache 一致性怎么处理？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

在非一致性 cache 系统中，CPU cache 和 DMA 访问的 RAM 可能不同步。CPU 给 DMA 数据前可能需要 clean；DMA 给 CPU 数据后可能需要 invalidate，具体顺序、区域、对齐和屏障依厂商要求。

## 原理拆解

clean 将脏 cache line 写回，invalidate 丢弃 cache 内容；错误地 invalidate 含有其他脏数据的同一 line 可能丢失 CPU 修改。接收缓冲区需防止 CPU 与 DMA 共享一条 line 中的无关数据，并防止 DMA 期间 CPU重新写入。

## 例子与推演

F7/H7 的 M7 示例应独占且按 cache line 对齐 DMA buffer，维护覆盖范围，并在规定时点执行。另一方案是正确配置不可缓存区，但仍需满足 DMA 可达性与访问顺序。具体函数、line 大小和 RAM 域查型号文档。

## 常见误区与失败边界

不能把本节泛化为“所有 STM32 DMA 都必须 clean”。volatile、禁优化或在代码中重复读取都无法自动解决 cache 一致性。

## 面试追问

接收后先 invalidate 就永远安全吗？答：不一定，DMA 前脏行、共享行、CPU 并行写入和推测填充等也需按官方流程处理。

## 动手练习与验收

画 CPU→DMA 和 DMA→CPU 两条时间线，标 clean/invalidate 和屏障点。验收：说明缓冲区独占、对齐、可达性；未做真实硬件一致性测试。
