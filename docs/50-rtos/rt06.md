# RT06 · FromISR API 与中断优先级上限怎么配合？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

ISR 使用明确支持中断上下文的 FromISR API，并遵守移植层的可调用中断优先级范围。单核 Cortex-M 常通过 BASEPRI 临界区保护内核；更高紧迫性的 ISR 不能随意访问被此机制保护的内核状态。

## 原理拆解

逻辑优先级与左移后的寄存器值分开核对。正确初始化 higherPriorityTaskWoken，调用后若唤醒更高优先级任务，使用适用 portYIELD_FROM_ISR 等宏请求切换。更高紧迫性 ISR 可先做极短硬件处理，再由安全优先级路径转交。

## 例子与推演

```c
/* 教学片段：名称和参数需匹配所选 FreeRTOS 移植。 */
BaseType_t woken = pdFALSE;
xQueueSendFromISR(queue, &sample, &woken);
portYIELD_FROM_ISR(woken);
```
同时检查发送返回值，队列满时不能在 ISR 等待。

## 常见误区与失败边界

“ISR 里函数名前加 FromISR 就万事大吉”忽略优先级约束和数据生命周期。优先级 0 常为最紧迫，不能只看数值方向。

## 面试追问

为何只有高优先级 UART ISR 调队列时崩溃？答：核对 configMAX_SYSCALL_INTERRUPT_PRIORITY、分组、实际 NVIC 值和断言。

## 动手练习与验收

写一张 ISR 名称、实际优先级、允许 API 表。验收：所有内核调用 ISR 合规，woken 每次正确初始化并处理满队列。
