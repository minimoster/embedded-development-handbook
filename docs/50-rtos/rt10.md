# RT10 · 任务创建、参数生命周期与软件定时器怎么设计？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

任务参数通常是传入的地址，不会自动复制目标对象或延长它的生命周期。静态/动态创建要核对栈单位与配置；软件定时器回调在服务任务上下文运行，应短小且避免阻塞整个定时器服务。

## 原理拆解

task entry应遵守API签名且通常不任意返回；退出用所选内核规定流程。多个定时器共享daemon执行能力，一个慢回调会影响其他回调。精准外设边沿通常交硬件timer，软件timer适合受控时延事件。

## 例子与推演

创建任务时传向main局部配置地址，main返回/该对象失效后任务读取就错；把配置放足够长寿命对象或复制到任务拥有存储。timer回调只发通知，让工作任务执行慢I/O。

## 常见误区与失败边界

“回调不是ISR所以可无限阻塞”会拖住所有timer工作。软件timer周期以tick和调度实现，不是准确硬件采样保证。

## 面试追问

多个相同任务用同一个参数指针会怎样？答：若指向循环内反复改写变量，各任务可能读到最终值，需独立配置与同步启动。

## 动手练习与验收

设计两任务+两timer参数拥有图，加入创建失败回滚。验收：回调有界，参数活到最后读取，内存单位按port核对。
