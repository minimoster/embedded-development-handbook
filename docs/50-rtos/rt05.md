# RT05 · 队列、任务通知和事件组的语义差别？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

队列传递有长度和容量的数据项；任务通知轻量地给指定任务发送状态/计数/位等；事件组表示共享条件位。先决定是否需保留每条消息、允许合并和一对多，再选机制。

## 原理拆解

FreeRTOS 队列通常复制 item 字节。若 item 是指针，复制的是地址，不是目标数据；发送成功只说明地址入队，不能释放或复用目标。通知计数与位模式有不同合并/覆盖规则，事件位不是数据队列。

## 例子与推演

一个任务等待“DMA 完成”适合通知；每条报警必须保留，可用有界队列并设计满队列策略；多个任务等网络就绪可考虑事件位。发送 buffer 指针需明确消费者何时归还。

## 常见误区与失败边界

“队列线程安全所以指针目标也安全”错误。满队列时无限等待可能在故障中锁死生产者，丢弃策略与统计应明确。

FreeRTOS标准队列在创建时有最大项数，按固定项大小复制，不存在由xQueueCreate建立无限容量队列的默认合同。队列满/空时的等待、超时和FromISR失败都需处理。事件组传位状态，任务通知可作轻量信号/计数，stream/message buffer另有生产者消费者条件，不把这些机制统称任意消息事件。

## 面试追问

多个样本完成但通知只见一次怎么办？答：按业务选择计数通知或队列，或明确允许只处理最新状态。

## 动手练习与验收

做满队列、超时和指针复用推演。验收：容量来自突发/消费上界，每个指针有明确拥有者和归还事件。
