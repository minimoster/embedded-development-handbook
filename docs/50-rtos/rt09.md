# RT09 · SPSC 环形缓冲怎样避免看似正确的竞态？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

单生产者单消费者队列可通过分离 head/tail 所有权与正确发布顺序设计；多个生产者、消费者或 DMA 参与后原合同失效。单核 ISR 场景还必须证明访问宽度、原子性与编译/架构顺序。

## 原理拆解

C++17原子版有两条发布边：生产者写slot后release-store head，消费者acquire-load head后才能读slot；消费者读完后release-store tail，生产者acquire-load tail后才可复用slot。自己独占的索引读可用relaxed。环满判定、容量是否留一格、索引回绕都应明确。普通变量和 volatile 不能普遍表达 C++ 线程同步。

## 例子与推演

容量 8、留一槽的 ring 最多放 7 项，head==tail 为空，next(head)==tail 为满。若需要完整 8 项，可用计数/单调计数器，但其并发和回绕证明重新设计。

固定模索引与单调计数器不是同一回绕证明：前者按数组容量计算next并留一槽，后者需证明无符号差值在最大未消费距离内可判空/满。示意原子顺序不证明所选atomic在目标上无锁，也不证明ISR/DMA可直接共用。

## 常见误区与失败边界

“只有一个写者就完全无竞争”仍有另一上下文读取。消费者提前 tail++ 可能让生产者复用尚未读取的数据。目标 atomic 未必 lock-free 或 ISR 可用。

## 面试追问

MPSC 如何改？答：不能只加一个 fetch_add，需分别解决槽位占用、提交顺序、容量与消费者看到未完成数据。

## 动手练习与验收

主机先测顺序语义与边界，再单独验证并发模型。验收：明确使用场景；主机顺序 ring 测试不宣称证明 ISR/DMA 并发安全。
