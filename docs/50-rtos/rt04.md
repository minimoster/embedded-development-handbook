# RT04 · 优先级反转、继承与死锁怎么解释？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

低优先级任务持有高优先级任务要用的锁，中优先级任务持续抢占低任务，使高任务被间接拖延，这是优先级反转。继承提高持锁者优先级以减轻反转；它不消除死锁，也不是完整实时证明。

## 原理拆解

A 高等待 L 低持有的 mutex，M 中不断运行；L 继承 A 的优先级后能完成临界区。多个 mutex 的 FreeRTOS 简化继承/回退行为需查版本与官方描述。锁顺序和有限持有时间仍重要。

## 例子与推演

所有任务统一按 bus_lock→buffer_lock 获取，避免任务甲/乙分别持有一个再等另一个。UART 慢日志不要放入保护传感器数据的锁内，否则临界区把 I/O 延时放大。

## 常见误区与失败边界

“有继承就不会死锁”错误。不要把提高所有任务优先级当修复；长临界区和抢占屏蔽仍可破坏 deadline。

## 面试追问

如何证明锁等待上界？答：分析所有持锁路径、嵌套、阻塞调用和调度配置，并结合目标实测。

## 动手练习与验收

画反转时间线与 ABBA 死锁图，各给独立修复。验收：锁序全局一致，临界区内无无界阻塞，说明继承机制限制。
