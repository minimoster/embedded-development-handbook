# IC01 · UART中断把队列塞满，偶发丢命令

原创场景，公开面经只提供主题联系，非原帖题目或公司题库。核对日：2026-10-10。主机状态模型、板级DMA、Flash断电和内核模块练习均未执行；下列验收是后续检查标准。

## 公开面经主题联系

[EN01](source-catalog.md#en01)/[EN05](source-catalog.md#en05) 的外设、中断与并发追问。下面具体故障情境为原创延伸。

## 故障场景

FreeRTOS 接收任务每次解析较慢，UART ISR 每收到一字节就发到长度为8的队列。短包正常，连续突发时协议命令丢失。有人建议在 ISR 中等队列空出来，或者用 printf 看每个字节。

## 先理解机制

中断是抢占现场的短处理，消费者任务才负责较重的解析。队列满说明生产和消费之间的容量/速度不匹配。成功“通知任务”不等于一帧已完整保存。

## 直接回答

我先量化字节到达率、最长消费者停顿和队列满次数。ISR 用 FromISR API、检查返回值，记录可观测的丢弃/溢出状态，再让任务完成解析。队列复制的是项的字节，传指针时仍需保证原数据存活。唤醒更高优先级任务后按该 port 请求切换。[FreeRTOS V11.1.0 queue.h](https://raw.githubusercontent.com/FreeRTOS/FreeRTOS-Kernel/V11.1.0/include/queue.h)

## 面试追问

1. “改用 FromISR 就一定正确吗？”还要核对实际 NVIC 优先级与允许调用内核的阈值。Cortex-M4F 的数字小代表更高逻辑优先级，不能把任务优先级的数字直觉套进去；启用 configASSERT 并检查优先级分组/编码。[官方 ARM_CM4F port](https://raw.githubusercontent.com/FreeRTOS/FreeRTOS-Kernel/V11.1.0/portable/GCC/ARM_CM4F/port.c)
2. “把队列加大就行？”只有有界突发、平均消费能跟上时才可能解决；长期过载需背压、限流或明确定义丢弃/重同步。不要在 ISR 内忙等消费者运行。
3. “想降低复制开销？”可用固定缓冲池加索引，但要能说明 ISR、解析任务与空闲池各自何时拥有该槽；不能把局部栈数组地址发出去。

## 常见误区与失败边界

忽略 errQUEUE_FULL；每次进 ISR 没将 woken 初始为 pdFALSE；在 ISR 阻塞/拿普通 mutex；把换行当作所有二进制协议的包边界。

## 动手练习（尚未执行）

用8槽模型输入序列号0…99，消费者每处理一次故意停顿；分别实现“丢新项+计数”与“暂停输入/背压”策略。再把固定池索引替换为数据字节，画完整归还路径。板上用 GPIO 脉冲测 ISR 时间，printf 放在任务里。

## 验收标准（尚未执行）

- 输入总数 = 已处理数 + 正在处理数 + 记录的丢弃数 + 仍排队数；停机核对时正在处理数为0，无静默丢失
- 每个池槽只有一个所有者，归还一次，绝不提前复用
- 过载结束后解析恢复；ISR 耗时有上界，非法内核调用配置被检测

## 版本与适用边界

FreeRTOS Kernel V11.1.0、单核 GCC ARM_CM4F port 为依据。SMP、Cortex-M0、厂商修改 port、不同 UART/DMA 接收模式需另核对，不把本卡参数直接复制到目标板。
