# DV08 · ioctl、sysfs、poll 的接口设计原则？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

选择已有子系统接口优先于自创 ioctl。ioctl 适合设备控制 ABI，sysfs 通常暴露简洁属性，poll 提供可读/可写等等待条件。接口一旦给用户使用，就需考虑兼容、权限、并发和可取消性。

## 原理拆解

ioctl 结构避免裸 long、指针大小依赖和含 padding 的未初始化输出；固定宽字段并设计版本/size 校验，兼容 32/64 位。sysfs 不适合随意传大块二进制或复杂协议。poll 条件必须与 read/write 一致。

## 例子与推演

配置请求包含 version、size 和固定宽度参数；未知字段/版本按定义拒绝或兼容。读取 sensor 数据用 read，配置速率可用已有子系统属性，状态等待可用 poll，不让应用轮询占满 CPU。

## 常见误区与失败边界

“只是内部 ioctl，可以随意改”会破坏已有应用/升级。复制整个未初始化内核 struct 可能泄露 padding 信息。

## 面试追问

如何保证新固件配旧程序？答：保持 ABI 或显式版本协商，并把旧/新组合放进兼容测试。

## 动手练习与验收

设计一个固定宽度控制结构并列 compat 问题。验收：参数范围、权限、版本、取消和错误码都明确；真实模块编译/接口测试待目标内核。
