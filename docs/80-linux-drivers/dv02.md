# DV02 · 为什么不能直接解引用用户指针？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

用户指针属于用户地址空间，可能无效、变化或触发缺页；内核需用适用的 copy_to_user/copy_from_user 等接口并处理失败。不能把地址检查一次当作后续永远有效，也不能在不允许睡眠上下文做可能缺页的复制。

## 原理拆解

用户可在复制间改变数据，所以先复制有界头并验证，再复制数据；长度加乘防溢出，必要时把一致的请求快照保存在内核对象中。对应 API 返回未复制字节等约定必须核对。

## 例子与推演

ioctl 请求含 count 和用户 buffer：限制 count、检查 count*sizeof(item) 溢出、分配允许容量、复制后验证每项。错误返回前归还资源，不在 spinlock 临界区进行可能睡眠的用户复制。

## 常见误区与失败边界

“用户传的地址看起来正常”不能作为验证。用 access_ok 后直接访问仍可能缺页或 race；地址宽度跨 compat ABI 也要设计。

## 面试追问

TOCTOU 怎么缓解？答：尽量使用复制后的快照进行验证/执行，明确不可变或重检策略，避免再次信任变化的用户字段。

## 动手练习与验收

做纸面恶意长度、无效指针、部分复制的路径分析。验收：所有长度有上限，错误不会泄露内核数据；真实内核测试需后续 KUnit/kselftest。
