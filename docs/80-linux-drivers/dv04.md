# DV04 · MMIO、ioremap 与寄存器读改写有什么风险？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

设备寄存器不是普通 RAM。内核应使用子系统/架构提供的映射与访问接口，并遵守访问宽度、顺序和副作用。寄存器读可能清状态，写可能 W1C；不能将所有位都用普通读改写。

## 原理拆解

物理地址、CPU 虚拟地址和 DMA 地址不同。ioremap 等获得适用 MMIO 映射，但不会自动理解寄存器语义。共享 RMW 可丢更新；硬件 set/clear 寄存器或适用锁能避免某类问题，仍需手册证明。

## 例子与推演

W1C 标志：写 1 清除指定事件；读出值再 OR 一个位后写回可能意外清其他事件。应只写需清的 mask，并注意硬件与驱动同时改变状态。

## 常见误区与失败边界

volatile 指针不等于 Linux 可移植 MMIO API。把设备地址映射用户态可能扩大权限/安全风险，应优先受支持驱动接口。

## 面试追问

为什么读寄存器后设备行为变了？答：检查 read-to-clear/FIFO pop、访问宽度、顺序和旁路读影响。

## 动手练习与验收

给普通 RW、W1C、read-to-clear 三类寄存器写操作表。验收：没有未核对芯片地址或直接内存读写示例，真实值必须查手册。
