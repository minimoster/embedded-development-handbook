# DV05 · Linux DMA mapping 与裸机 DMA 为什么不同？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

驱动不能把 CPU 指针直接当 DMA 地址。需通过 DMA API 获取设备可使用的 dma_addr_t，检查映射错误、地址掩码与生命周期；streaming 与 coherent 映射的同步规则不同。

## 原理拆解

IOMMU、总线地址转换、cache 和设备寻址能力使地址空间不同。streaming buffer 的 CPU/设备拥有权转换需要适用 map/sync/unmap；coherent 也不代表所有读写顺序天然正确，仍需必要屏障。

## 例子与推演

发送：准备 buffer→dma_map_single 指定方向→检查错误→编程设备 DMA 地址→完成→unmap/同步并归还。接收方向相反，CPU 不能在设备仍拥有时任意读取/修改。具体代码需匹配目标内核与设备。

## 常见误区与失败边界

virt_to_phys 不等于合法 DMA mapping。栈、vmalloc 区和高层 buffer 的适用规则要查 API，不能随便给设备。

“ARM总线地址恒等物理地址”不是可移植假设；主机桥/IOMMU等可引入转换。dma_alloc_coherent 返回 CPU 可访问地址和设备 dma_handle 两个视角，仍需地址能力、失败处理和顺序屏障。旧版本一次能分配4MiB之类实测数不能变成所有架构上限。

## 面试追问

coherent 分配就无需任何屏障吗？答：不成立，cache 一致性与操作顺序不同，描述符先填字段后设置有效位需明确顺序。

## 动手练习与验收

画三种地址和 CPU/device ownership 时间线。验收：方向、映射失败、取消、卸载都配对释放；未声称实板 DMA 已验证。
