# DV06 · 内核 mutex、spinlock 与中断上下文怎么选？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

锁类型选择取决于是否允许睡眠、访问者与内核配置。普通非 PREEMPT_RT 语境中 spinlock 临界区不能睡眠，mutex 用于可睡眠上下文。PREEMPT_RT 会改变部分锁的实现语义，必须限定讨论范围。

## 原理拆解

若进程持锁时被访问同一锁的本 CPU ISR 打断，可产生自死锁，因此适用 irqsave 等方式与访问路径一起设计。raw_spinlock_t 和普通 spinlock_t 在 RT 中不能混讲。锁不仅保护单字段，还保护状态关系。

原子读改写不是自动独占整个设备或保护多个字段的不变量；local_irq_disable 只影响本 CPU 的相应中断，不构成多核互斥。RCU 允许读者与更新者重叠，旧对象的回收要等相关宽限期，另见 [DV11](dv11.md)。

## 例子与推演

共享“队列+ready 标志”由同一保护规则维护；临界区仅做短状态更新，耗时处理转到线程上下文。copy_to_user、分配带睡眠 flags 和等待 I/O 不应塞进普通原子上下文。

## 常见误区与失败边界

“spinlock 是忙等，所以在任何 Linux 配置都完全一样”错误。把关本 CPU 中断当多核互斥也错误。

## 面试追问

怎么查锁反转/死锁？答：统一锁序、缩小临界区，使用适用 lockdep 配置并记录执行上下文。

## 动手练习与验收

为进程/硬 IRQ/工作线程三者画锁矩阵，限定 non-RT 或 RT。验收：每个临界区说明可否睡眠及中断状态恢复规则。
