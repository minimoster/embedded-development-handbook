# DV01 · 字符设备、file_operations 和用户态 fd 如何连起来？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

字符设备驱动通过设备号与 VFS 接口连接用户程序，file_operations 提供 open/read/write/ioctl/poll 等行为。/dev 节点只是入口，实际硬件状态和每次打开的上下文由驱动管理。

## 原理拆解

用户 fd 指向内核打开文件相关对象，多个 fd 可共享同一打开文件语义。file->private_data 常用于每次打开的上下文或设备引用；释放时需与设备移除、异步工作和引用计数协调。注册成功不等于硬件初始化完成。

## 例子与推演

采样字符设备的 read：无数据则阻塞或按 O_NONBLOCK 返回 EAGAIN，有数据复制到用户并返回实际长度；poll 报告可读条件，必须与 read 使用同一状态规则。

## 常见误区与失败边界

只实现 read 然后永远返回请求长度会骗过应用。设备节点权限和生命周期不应凭 mknod 成功推断正确。具体 cdev/设备注册 API 固定内核版本再写。

## 面试追问

设备拔出后用户 fd 还开着怎么办？答：标记离线、停止异步访问、唤醒等待者、按引用释放并给出一致错误。
