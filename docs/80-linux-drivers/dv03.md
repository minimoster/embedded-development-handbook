# DV03 · platform 驱动、设备树与 probe 的关系？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

设备树描述硬件实例及连接/资源，可为多种总线创建设备。SoC内存映射设备常用platform_driver/platform_device；I²C传感器通常绑定i2c_driver/i2c_client，不应把所有DT节点都归为platform设备。对应总线驱动提供匹配与操作实现。匹配后 probe 获取资源并初始化设备；compatible 不是随意给字符串，需要遵守对应 binding 和驱动支持。

## 原理拆解

地址、IRQ、时钟、reset、regulator、GPIO 等依硬件描述和子系统接口获取。依赖尚不可用时可能需要 deferred probe，不把所有失败都当硬件不存在。设备树不适合任意塞业务策略或应用配置。

## 例子与推演

一颗 I²C 传感器节点指定总线地址、compatible 和中断 GPIO；I²C核心创建设备并匹配i2c_driver，驱动根据binding取得资源，设备成功初始化才提供用户接口。修改 DTB 不会凭空产生未编写或未启用的驱动。

## 常见误区与失败边界

“设备树就是驱动代码”错误。DTB 与 kernel image/board 必须匹配，源 DTS 生效还要确认实际启动加载的产物。

## 面试追问

probe 为什么没调用？答：查节点 status、compatible、总线枚举、驱动编译/加载、match table 与真实加载 DTB。

## 动手练习与验收

为虚构设备只画 DTS 资源关系，不造真实地址。验收：每个属性有 binding 依据，能区分匹配失败、依赖延迟和初始化失败。
