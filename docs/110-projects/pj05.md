# PJ05 · 面向 EE 背景怎样连接硬件优势与软件短板？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

电路、采样、时序与信号处理能力能帮助理解真实数据链，但软件岗位仍需指针/所有权、并发、接口、测试与部署。以一条完整数据链展示两侧能力，避免只证明会使用仪器或会跑模型。

## 原理拆解

同一ADC项目同时分析源阻抗/参考噪声和buffer生命周期/队列延迟，才连接硬件与软件。边缘AI再加入前处理、量化、推理内存与端到端延迟，但需要官方工具与目标模型验证，不能从桌面推理速度推 MCU 性能。

## 例子与推演

可先完成可靠采集/通信基线，再把一个有许可证的小模型放成可替换处理模块；测无模型与有模型的内存、响应和失败行为。没有目标设备实测，就称主机原型。

## 常见误区与失败边界

不要为了“AI”忽略串口协议、掉样和恢复；不要在简历上把尚未完成方案当部署经验。模型质量与系统可靠性是两个指标集。

## 面试追问

为什么从传统嵌入式延伸到AI应用？答：表达自己的实际兴趣与证据，不把手册写的理由当个人观点。

## 动手练习与验收

列自己已有课程/实验的可展示证据，挑一条可补软件闭环的主线。验收：所选方向有小而完整可复现成果，不杜撰履历。
