# PJ03 · 面试项目介绍怎样从功能讲到工程证据？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

用目标/约束→架构→本人负责部分→关键机制→实际验证→问题与权衡组织。先讲可核实的内容，明确哪些是独立完成、团队配合、课程练习或设计方案，不借模板编造经验。

## 原理拆解

工程问题通常落在数据/时间/资源/错误四条线。面试官追问是在检查你是否理解链路与边界；只讲“使用 FreeRTOS 提高效率”缺因果。先给为什么，再给实现和测量。

## 例子与推演

一个90秒练习回答：解决什么→输入输出→主方向→数据流→我做了哪些→验证哪些边界→还没验证什么。随后准备 DMA buffer、队列满、优先级、异常恢复四张白板图。

## 常见误区与失败边界

不用虚构企业、板卡、团队规模、性能提升百分比。未测数据说计划如何测；不懂部分说清假设与查证路线，不背源材料错误结论。

## 面试追问

“为何这么设计”怎么答？答：列至少两种方案、具体约束和损益，再给选型证据。

## 动手练习与验收

录音2分钟介绍，逐句标可验证证据；验收：没有无法证明的指标，所有技术名词能在源码/图/日志上落地。

## 来源与适用范围

- [FreeRTOS Kernel Book：中断与同步](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/main/ch07.md)：以单核 Cortex-M 常见移植为教学语境；项目需固定实际内核版本。
- [CMake：Toolchains](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html)：滚动文档；使用前核对本机 CMake 版本。
