# PJ01 · 怎样做一个可答辩的 MCU 数据采集项目？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

练习项目可选定时器触发采样→DMA缓冲→RTOS处理→串口/网络输出。重点是可解释的时序、所有权、容量和故障恢复；这是一份练习方案，不是声称读者已有这个项目。

## 原理拆解

先无 RTOS 验证单链，再拆任务。采样与处理边界用双缓冲或队列，明确谁何时可读写。处理最坏时间应小于可用周期或采用背压/丢弃；MCU/RTOS/库版本和引脚必须记录。

## 例子与推演

交付物：数据流图、时钟树、任务/ISR优先级表、容量预算、波形与异常日志。主机先测滤波/解析/回绕；板上测真实触发、DMA所有权、延迟和漏样。本仓库不给虚构吞吐指标。

## 常见误区与失败边界

把 Cube 生成代码加串口打印当完整项目，无法解释中断/DMA/缓冲区就是薄弱点。使用M4板不要展示自己不存在的M7 D-cache实验。

## 面试追问

面试问最难问题怎么讲？答：讲实际失败、证据、排除过程、修复和复验；没有遇到可讲设计验证，不能虚构。

## 动手练习与验收

按四次里程碑验收：轮询→IRQ→DMA→RTOS。每次保存正常/异常比较。验收：每步能重现，未上板项目只称主机/设计练习。

## 来源与适用范围

- [ST AN4776：通用定时器](https://www.st.com/resource/en/application_note/an4776-generalpurpose-timer-cookbook-for-stm32-microcontrollers-stmicroelectronics.pdf)：STM32 定时器入门；具体功能以所选芯片 RM 为准。
- [FreeRTOS Kernel Book：中断与同步](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/main/ch07.md)：以单核 Cortex-M 常见移植为教学语境；项目需固定实际内核版本。
- [ST AN4839：F7 / H7 一级缓存](https://www.st.com/resource/en/application_note/an4839-level-1-cache-on-stm32f7-series-and-stm32h7-series-stmicroelectronics.pdf)：仅针对相应 Cortex-M7 F7/H7，不能套用于所有 STM32。
