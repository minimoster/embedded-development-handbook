# C04 · volatile、atomic 与内存屏障怎样分工？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

volatile 用于让实现按其规则执行可观察的访问，常用于 MMIO；它不保证复合操作原子，不形成线程同步，也不普遍替代硬件屏障。线程共享状态使用原子或锁，设备顺序遵循芯片与架构规定。

## 原理拆解

counter++ 仍包含读、算、写。两个执行上下文可覆盖对方结果。C++ 数据竞争本身可导致 UB；原子操作和 acquire/release 可建立 happens-before。编译器屏障、CPU 屏障与 cache clean/invalidate 解决不同层次的问题。

## 例子与推演

任务写数据后发“就绪”，消费者看到就绪后必须能看到数据。使用 release store 与 acquire load 可以表达发布关系；把就绪标志改成 volatile 不能证明这种关系。MMIO 应使用厂家寄存器定义与规定访问宽度。

## 常见误区与失败边界

“volatile 让变量放到内存”不是严谨定义。“单核所以无需同步”也错，任务切换和中断同样可交错。不能将主机 std::atomic 假定为所有 MCU 上无锁。

## 面试追问

为什么 DMA 写了内存，CPU 却读到旧数据？答：除访问顺序外，还要检查非一致性 cache、缓冲区区域和维护时机。

## 动手练习与验收

在 C++17 主机上做 release/acquire 发布实验；另画 MMIO、共享 RAM、DMA RAM 的责任表。验收：每种机制对应明确问题，不能仅凭测试成功证明无竞争。
