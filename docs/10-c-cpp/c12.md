# C12 · 整型提升、位运算与移位如何写得可移植？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

先确定宽度与符号，再操作位。小整数会经历整数提升；移位数负数或不小于类型宽度等会导致UB。位掩码常使用明确的无符号固定宽度类型，并验证输入位索引。

## 原理拆解

表达式1<<31可能以signed int计算并触及不可表示边界；使用UINT32_C(1)并限制bit<32更清楚。混合有符号/无符号比较可改变语义，边界运算先检查再做。寄存器位宽与实际访问类型也必须匹配。

语言保证的位宽下限、ABI数据模型与具体芯片寄存器宽度要分开。sizeof以char为单位，CHAR_BIT不由C语言固定为8；uint32_t存在时才提供恰好32位的无符号类型。unsigned long在LP64和LLP64中大小可能不同，不宜用于固定32位寄存器定义。函数/对象/成员指针的表示也不必统一，地址应按目标接口类型使用。

语言版本也要区分：32位int下，C11的`1 << 31`因结果不能由int表示而是UB；C++17按对应无符号类型的可表示性规定这一左移，不能照搬C11结论。下面统一采用无符号掩码，移位次数仍需小于提升后左操作数的宽度。

## 例子与推演

```c
#include <stdint.h>
#include <stdbool.h>
bool bit_mask(unsigned bit, uint32_t *out) {
    if (bit >= 32 || !out) return false;
    *out = UINT32_C(1) << bit;
    return true;
}
```
避免用a-b比较排序大小，防止signed溢出。

```c
#include <inttypes.h>
#include <stdio.h>
#include <stdint.h>
static void report_size(size_t n, uint32_t value, int *p) {
    printf("count=%zu value=%" PRIu32 " ptr=%p\n",
           n, value, (void *)p);
}
```
格式串与可变参数的实际类型必须匹配：sizeof用%zu，固定宽度值用inttypes宏，对象指针用%p并转void*。不能把地址强塞%08x，再据打印结果证明布局；函数指针不能据此类推为void*。

## 常见误区与失败边界

把uint8_t左移后以为仍按8位计算，忽略提升；把负signed右移结果当所有实现统一合同。无符号回绕有定义也不代表业务逻辑自动正确。

## 面试追问

为什么size_t与-1比较常出错？答：负数可能转换成巨大无符号值，先确认错误码类型和返回语义。

## 动手练习与验收

测试bit 0、31、32、空输出以及极端加法。验收：合法位得到精确mask，非法输入无移位，编译开启转换警告。
