# C08 · C++ RAII、unique_ptr 与错误路径有什么价值？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

RAII 将资源生命期绑定到对象：构造成功获得资源，析构释放资源。它适用于内存、文件、锁和设备句柄。unique_ptr 表达单一所有权；shared_ptr 只在确需共享生命期时用。

## 原理拆解

作用域退出会析构已构造对象；移动转移所有权而不是复制释放责任。使用 RAII 可以减少 early return 中漏释放，但不能自动决定 ISR 安全性、实时性或硬件关闭顺序。禁异常环境也能利用作用域析构管理资源。

unique_ptr不使用共享引用计数，可以作为vector等容器元素。元素所做操作须满足各操作的类型约束，例如push_back(std::move(p))转移拥有者，普通复制unique_ptr则是编译错误。容器重分配可移动unique_ptr包装对象，但其管理的独立堆对象通常没有因此搬迁；指向包装对象的引用与指向受管理对象的观察指针是两种生命期问题。auto_ptr在C++17已移除，不作为本仓库方案。

## 例子与推演

```cpp
#include <memory>
struct Sensor { int value = 0; };
auto a = std::make_unique<Sensor>();
auto b = std::move(a);
/* b 拥有对象，a 不再拥有；不要解引用 a。 */
```
文件句柄包装器应禁止拷贝并定义移动语义，析构器不能抛出异常。

```cpp
#include <memory>
#include <vector>
std::vector<std::unique_ptr<int>> owners;
auto one = std::make_unique<int>(8);
owners.push_back(std::move(one));
/* one为空，owners.back()拥有该对象；不能再解引用one。 */
```
reset释放当前拥有资源，release只交出指针并解除拥有关系；release之后必须立即由其他明确拥有者接管，否则依然会泄漏。

## 常见误区与失败边界

shared_ptr 的引用计数不使 Sensor 的字段线程安全。RAII 类若可随意拷贝，可能导致重复关闭同一 fd。MCU 上要评估分配、异常和运行库开销。

## 面试追问

unique_ptr 可以管理非 new 资源吗？答：可以使用自定义 deleter，但接口应表示资源约定，并防止不匹配释放。

## 动手练习与验收

实现 movable、non-copyable 的主机 fd 包装器；测试成功、提前返回和移动三条路径。验收：一个有效 fd 最终仅关闭一次。
