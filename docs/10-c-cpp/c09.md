# C09 · 引用、拷贝、移动和完美转发如何区分？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

引用是别名；拷贝按类型的拷贝语义创建另一个对象；移动允许目标接管源的资源，但源仍是合法对象，具体状态由类型合同决定。std::move 只是转换成可移动的表达式，不执行移动本身。

## 原理拆解

是否调用移动构造取决于重载解析和目标操作。const 对象转成 const 右值通常仍无法调用需要 T&& 的移动构造。转发引用加 std::forward 用于保留调用方值类别，普通 T&& 与模板中的推导规则应区分。

表达式的值类别与变量声明的引用类型不同：命名T&&参数在函数体中是左值表达式，std::forward<T>(arg)按推导结果恢复调用者类别，std::move(arg)统一转换为右值引用表达式。引用的ABI实现是否有指针存储未由语言统一规定。直接绑定临时对象可能延长寿命，但引用参数、返回引用等有不同规则，不能把“右值引用一出现就延寿”作为通则。

## 例子与推演

```cpp
#include <string>
#include <utility>
std::string a = "sensor";
std::string b = std::move(a);
a.clear(); /* 合法；不能依赖移动后 a 一定为空。 */
```
面试先画资源所有权，再判断哪个构造函数可匹配。

## 常见误区与失败边界

“move 后源对象销毁”错误。“移动总是 O(1)”错误，小对象或特定容器/分配器情形可能仍做元素操作。不要返回局部变量时无条件 std::move，可能妨碍某些消除路径。

## 面试追问

如何设计只可移动的驱动句柄？答：删除拷贝，移动后令源无效，析构仅释放有效资源。

## 动手练习与验收

给自定义资源类打印构造、移动和析构；验收：不把可选拷贝消除当固定调用次数，能解释关闭责任。
