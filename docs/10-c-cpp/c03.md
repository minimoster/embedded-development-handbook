# C03 · const 能保证什么，不能保证什么？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

const 限制通过某个访问路径修改对象的能力。它不自动使对象线程安全，也不等于编译期常量。const int * 是不可经此指针改值；int * const 是指针自身不可改指向。

## 原理拆解

对象原本若为非 const，可以通过其他合法别名改变它；但强行去掉真正 const 对象的限定再写入会触发未定义行为。顶层与底层 const 要分开看，函数接口的只读视图不等于全局不可变。

## 例子与推演

```c
int value = 4;
const int *view = &value;
value = 5; /* 合法，view 随后读到 5 */
int * const owner = &value;
*owner = 6; /* 合法，owner 本身仍指向 value */
```
寄存器接口还常见 const volatile：每次读取可能变化，但该访问路径不允许写。

## 常见误区与失败边界

把 const 指针称为“线程安全指针”没有依据；它的目标可被别的线程改写。const 与 volatile 可共存，含义不同。

## 面试追问

C 的 const 局部整数为什么不总能用作要求整数常量表达式的场合？答：C 与 C++ 的常量表达式规则不同，不可混讲。

## 动手练习与验收

给四种 const/指针组合写合法与不合法赋值，要求编译器对不合法语句报错。验收：逐条解释是值不可写还是地址不可改。
