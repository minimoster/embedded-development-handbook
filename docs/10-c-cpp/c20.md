# C20 · lambda 捕获怎样跨越异步回调的生命周期？

学习优先级：P0。语言基线：C++17；先读 C10 回调合同、C16 拥有/观察关系。

## 直接回答

lambda 是闭包对象，捕获规则决定它保存了什么。值捕获保存副本，引用捕获借用原对象，捕获 this 通常保存对象地址；闭包本身活得久，不会自动让借用目标活得久。异步执行前先画拥有者、闭包、目标对象和注销的生命期。选择拥有式捕获、weak_ptr观察或明确外部生命期保证，再决定放进什么回调容器。

## 原理拆解

[x] 得到捕获时的值副本，不随之后的 x 更新；[&x] 访问原对象，原对象结束生存期后执行即有危险。mutable 允许修改值捕获在闭包中的副本，不把修改送回原变量，也不提供线程同步。捕获一个裸指针的值，只复制地址；目标对象的寿命仍由外部负责。

[this] 不复制整个对象，异步成员访问可能碰到已销毁对象。C++17 的 [*this] 复制对象，但对象内部的裸指针、引用和资源语义仍需检查。shared_ptr 值捕获延长所管理对象的生命期，可能形成“对象拥有回调、回调拥有对象”的环。weak_ptr不延长目标寿命，调用时 lock 的临时强引用既决定是否可访问，也保持本次访问期间的生命期。

C++14 起初始化捕获可以移动 unique_ptr 进闭包。这个闭包不可复制，不能直接放入要求可复制目标的 C++17 std::function。可以用模板接收实际闭包类型，或改成有明确共享意义的可复制回调。泛型lambda的参数须写 auto，不是省略参数类型。

## 例子与推演

```cpp
#include <memory>
#include <utility>
auto payload = std::make_unique<int>(37);
auto once = [saved = std::move(payload)] { return *saved; };
/* payload为空；once拥有这份对象，且不可复制。 */
```

一次性执行器可以移动保存 once；不得因为“lambda语法很短”就假设执行器内部一定不分配。是否复制、移动、跨线程、取消、并发执行，都要写在执行器接口中。

```cpp
std::weak_ptr<int> observer = std::make_shared<int>(37);
auto inspect = [observer] {
    if (auto held = observer.lock()) return *held;
    return -1;
};
```

这段 weak_ptr 创建后没有任何持续强拥有者，临时 shared_ptr 在第一行结束时销毁，所以 inspect 得到失败分支。实际任务需由明确拥有者先持有对象；这个反例用于检查“谁在保持生命期”，不是认为 weak_ptr失灵。若目标字段由别的线程修改，lock成功也仍不等于字段同步。

## 常见误区与失败边界

- 返回引用捕获局部变量的lambda不会自动延长局部变量寿命
- [=] 中对成员的使用可能涉及 this；不能据“等号”认定所有目标都已复制
- expired 检查后再使用以前保存的裸指针存在窗口，直接 lock 并在 held存活期间操作
- 生命周期安全不等于数据竞争安全；多个闭包共享同一对象仍须同步
- 清空回调槽不等于停止已在执行的回调；资源销毁需取消并等待在飞行工作退出
- C普通函数指针不能携带捕获状态；用 C10 的函数指针加上下文模式进行边界适配

## 面试追问

为什么 shared_ptr 捕获会让设备迟迟不关闭？答：闭包或异步队列可能是最后一个强拥有者，释放时机依赖队列清理；若目标也拥有闭包，还可能形成强引用环。

move捕获是否保证回调只能执行一次？答：只是资源进入闭包，并不限制调用次数；一次性语义需要执行器合同或显式状态。
