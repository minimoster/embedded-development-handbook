# C22 · 重载、覆盖、名字隐藏与默认参数怎样决定一次调用？

学习优先级：P1。语言基线：C++17；以可复现调用决策取代“静态/动态多态”口诀。

## 直接回答

先按静态类型查找名字并做重载解析，再看选中的函数是否虚派发。派生类同名声明可能隐藏基类整组名字；using可以把基类重载带回查找。override检查一个声明是否真正覆盖基类虚函数，含参数、cv与ref限定匹配；返回类型可在规则允许时协变。默认实参按调用处的静态声明取得，函数体则可能按动态类型选择。

## 原理拆解

重载是一组可见同名函数参与参数匹配，不是只看名字相同。返回类型独自不同不能构成普通函数重载。覆盖不要求在派生类重复写virtual，也不要求基类成员对派生代码可见；访问控制和覆盖关系是不同检查。成员函数加上const或引用限定符后，可能变成另一个签名，此时override能及早报错。

名字隐藏发生在名字查找阶段，即使基类某个重载参数更合适，也可能根本没有进入候选集。using Base::read带回名字，不会自动让每个派生同名函数成为覆盖，也不改变某个virtual函数的final overrider。显式 Base::read调用限定版本会抑制普通虚派发。

默认参数不是运行时选择的一部分。接口基类和覆盖函数给不同默认值，会让同一个对象通过不同静态类型调用时产生不同参数。通常只在公共接口统一默认值，或设计无默认参数的虚函数加非虚包装层。

## 例子与推演

```cpp
struct Device {
    virtual ~Device() = default;
    virtual int read(int channel = 1) const { return channel; }
};
struct Mock : Device {
    int read(int channel = 2) const override { return 10 + channel; }
};
```

Mock对象d经Device&引用b调用b.read()，默认channel为1，但虚派发到Mock实现，结果11。d.read()经Mock声明取得2，结果12。b.read(3)得到13；b.Device::read()是显式限定调用，执行Device版本得到1。

若Mock声明 int read(double) 而没有 using Device::read，基类的read(int)可能被名字查找隐藏。若写 int read(int) override却漏const，编译器必须拒绝这个override声明。把这类编译错误分清，比凭运行输出推断“谁覆盖谁”更稳定。

## 常见误区与失败边界

- 派生函数同名不必然覆盖；检查完整签名与基类virtual属性
- 可协变的返回指针/引用须满足类关系与限定规则，不是任意返回类型都能改
- inline virtual合法；inline关键字与运行时是否间接调用不冲突
- 纯虚函数可以有类外定义，纯虚析构必须满足被调用所需定义；=0不是虚表槽值规范
- 构造/析构期间虚调用遵守当前构造层次，不能用它调用尚未构造好的派生对象逻辑
- 构造函数不能声明virtual；所谓“虚构造”工厂/clone是另一个惯用接口

## 面试追问

private虚函数能被覆盖吗？答：可以；覆盖判断不取决于它是否可被派生代码直接调用，调用访问权限单独核验。

为什么不在每个派生类写自己的默认值？答：默认参数与派发阶段不同，会形成静态类型相关的调用差异，容易使接口惊讶。
