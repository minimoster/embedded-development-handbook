# C10 · 回调函数、函数指针和上下文对象怎么设计？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

C 回调常用函数指针加 void* 上下文，避免只能访问全局变量。调用约定、参数签名、上下文生命周期及回调线程/中断环境都属于接口合同。

## 原理拆解

函数指针不能随意强转后用不匹配签名调用。C++ 捕获 lambda 通常不能直接转换为普通 C 函数指针；可用静态 trampoline 将 ctx 转回对象。异步注销必须处理已在飞行中的回调。

## 例子与推演

```c
typedef void (*on_sample_fn)(void *ctx, int sample);
struct sink { on_sample_fn fn; void *ctx; };
void emit(struct sink s, int value) {
    if (s.fn) s.fn(s.ctx, value);
}
```
ctx 指向的对象必须活到最后一次 emit 完成；栈上的 ctx 不能逃逸到长期任务。

## 常见误区与失败边界

只清空回调指针不等于已同步停止执行。ISR 回调不能悄悄调用阻塞、日志锁或堆分配。函数指针的 null 检查不能解决并发注销竞争。

## 面试追问

如何安全销毁订阅者？答：先停止产生新回调，再等待或同步在飞行回调完成，最后释放 ctx。

## 动手练习与验收

实现带 ctx 的采样回调并给两个独立实例使用；验收：无全局实例状态，并写明同步/异步和销毁流程。
