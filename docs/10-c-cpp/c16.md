# C16 · shared_ptr、weak_ptr 与循环引用如何判断？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

shared_ptr 共享对象生命期，weak_ptr观察而不增加强引用计数，可在需要时lock得到受控共享所有权。双向关系都用shared_ptr可形成循环，单纯离开作用域不能释放它们。

## 原理拆解

引用计数安全与对象字段安全不同；同一对象的读写仍需要同步。弱引用lock失败表示对象不再可获得，并非持有过raw pointer就可继续用。共享所有权更难分析实时开销和释放时机。

不同shared_ptr包装对象共享同一控制块时，其引用计数更新的线程安全不等于目标字段安全；多个线程同时读写同一个shared_ptr对象也不能直接按“计数原子”忽略竞争。C++17可用互斥保护这个包装对象，或采用标准提供的shared_ptr原子访问函数。weak_ptr::lock在一个原子判断/获取中返回强拥有者或空指针；先expired再用以前保存的裸指针并不建立保护。对象析构与控制块释放也不同：弱拥有者可继续使控制块存在。

## 常见误区与失败边界

重复用同一raw pointer创建多个独立shared_ptr会造成重复释放；shared_from_this也有初始化合同。无明确共享需要时优先独占或非拥有视图。

shared_ptr是共享所有权，不是所有指针的默认升级。节点拥有回调而回调捕获节点shared_ptr也会形成环，异步捕获见C20。不要照抄未经验证的手写计数器类：指针递增与计数值递增不同，赋值还要覆盖自赋值、原目标释放、异常路径与并发。这里使用标准智能指针并测试析构责任，不把教学计数器宣称为生产替代品。
