# C15 · class/struct、访问控制与 const 成员函数的真实边界？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

C++ class 与 struct 主要默认成员/继承访问不同，其余都可有方法、继承和构造。public/protected/private 控制源级访问，不是内存加密。const成员函数通常限制经this修改非mutable成员，不自动保护指针目标。

## 原理拆解

封装让不变量由接口维护：例如capacity不能被外部随意修改。const方法仍可触及共享对象或外部状态，所以也不等同纯函数/线程安全。派生类能否访问基类私有成员与对象布局不是一回事。

继承方式控制基类public/protected成员在派生接口中的可访问性；基类private成员仍不能由派生成员函数直接访问。protected还有通过派生对象表达式访问等限制，不能只背二维勾叉表。const对象可以读取可访问的非const数据成员，const成员函数也能读取非const字段；它主要限制经当前this进行的修改及可调用成员函数集合。

## 例子与推演

```cpp
class Buffer {
public: int size() const { return size_; }
private: int size_ = 0;
};
```
若成员是int*，const方法不能改该指针成员本身，但可能修改其非const目标，需接口自律。

## 常见误区与失败边界

“struct 没有封装”“private 防止黑客访问”都错误。访问控制失败是编译期规则，不应拿错误强转绕过类型安全。

## 面试追问

C++三大特性够描述所有差异吗？答：封装/继承/多态是教学摘要，C++还包括泛型、RAII等，讲具体机制更重要。

## 动手练习与验收

为Buffer定义容量/长度不变量与只读接口。验收：改变内部表示不会要求调用方改源码，const接口合同明确。
