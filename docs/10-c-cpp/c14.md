# C14 · memcpy、memmove 与字符串 API 怎样避免越界？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

memcpy 复制已知长度字节，源/目的重叠不满足其合同；memmove 支持重叠。strcpy/strlen 等零结尾函数要求有效终止符，不能直接用于任意二进制或网络buffer。

## 原理拆解

复制前分别证明源可读长度与目的容量，检查长度运算溢出。字符串的结束零也要占容量。memcpy可用于受控对象表示转移，但不能凭字节拷贝构造任意含资源的C++对象。

## 例子与推演

```c
#include <string.h>
char s[6] = "abcd";
memmove(s+1, s, 4);
s[5] = 0; /* 得到 aabcd */
```
若用memcpy复制这段重叠区域，行为不受合同保证。

## 常见误区与失败边界

strncpy 不等于自动安全的strcpy：截断时可能无终止零，且有填充语义。字节数与元素数混淆会在数组拷贝出错。

strlen返回size_t；strstr返回首个匹配位置指针或空指针，空模式匹配起始位置。strcmp/memcmp的字节比较按unsigned char解释，返回值只承诺符号而不承诺一定为-1/0/1。memset把int参数转换为unsigned char并填各字节，不表示任意对象都构造成该整数值。返回一个局部指针变量中保存的调用方buffer地址，不会因这个局部指针变量结束而使调用方buffer失效。

## 面试追问

安全复制怎么定义？答：明确容量、是否允许截断、返回值与终止规则，不能只换API名称。

## 动手练习与验收

测空、最大容量、重叠及含零二进制数据。验收：不运行已知UB去猜结果，每个复制有读写区间证明。
