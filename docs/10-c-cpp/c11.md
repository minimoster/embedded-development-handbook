# C11 · 虚析构、虚函数与对象切片有什么区别？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

多态基类若允许通过基类指针 delete 派生对象，通常应有虚析构。虚函数实现动态派发；按值把派生对象赋给基类会切片，只保留基类部分。避免把接口多态和资源所有权分开讨论。

## 原理拆解

构造/析构阶段的虚调用规则不同于完整派生对象运行时；不要依赖构造函数调用覆盖方法初始化派生字段。基类析构与派生析构顺序共同释放资源，std::unique_ptr<Base> 也不能修复非虚析构基类的错误删除合同。

标准定义虚派发的效果，并未要求每个对象恰有一个四字节vptr或每类恰有一表。多继承/虚继承可有多个子对象及虚表组；构造期间还可能使用不同虚表。Itanium等特定ABI可帮助理解实现，但具体偏移和.rodata/.data.rel.ro位置仍须由编译选项、重定位与链接脚本证实。

## 例子与推演

```cpp
struct Device { virtual ~Device() = default;
    virtual int read() = 0; };
struct Mock final : Device { int read() override { return 7; } };
```
通过引用/指针操作 Device，避免将 Mock 按值复制成 Device。

## 常见误区与失败边界

“有虚函数就自动有虚析构”错误。虚表是常见实现但具体布局非标准固定合同，不用背特定编译器偏移当跨平台知识。

inline virtual合法，纯虚函数也能在类外有定义；纯虚析构若被使用须有定义。构造函数声明virtual不合法，工厂/clone的“虚构造”称呼不是例外语法。CRTP确实使用模板与继承，析构仍是运行时对象生命期事件；非虚析构合理性来自不允许经该基类指针删除派生对象的设计合同。

## 面试追问

嵌入式一定不能用虚函数吗？答：需评估内存/调用与可测试接口收益，不能一律禁止或忽略成本。

## 动手练习与验收

构造一个接口+mock，用unique_ptr管理并测试析构路径。验收：所有所有权删除合法，能解释按值/引用传递差异。
