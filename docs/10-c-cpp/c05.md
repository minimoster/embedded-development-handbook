# C05 · 未定义行为、未指定行为与实现定义如何回答？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

未定义行为没有语言标准给出的执行要求；未指定行为允许多个结果且无需文档选定；实现定义要求实现记录其选择。讨论结果前，应先判定行为类别和目标 ABI。

## 原理拆解

有符号整数溢出、越界、失效对象解引用和某些错误移位均可为 UB。普通 char 的符号性属于实现选择。求值顺序要按具体语言版本和表达式规则分析，不能用一次打印结果倒推标准。

## 例子与推演

```c
#include <stdint.h>
uint32_t elapsed(uint32_t now, uint32_t then) {
    return now - then; /* 无符号减法按模 2^32 */
}
```
不要靠 signed int 溢出做 tick 回绕。若时钟可跨多个周期，模差仍不能还原真实经过时间。

## 常见误区与失败边界

UB 不等于“随机值”或“一定崩溃”；优化器可能据此改变后续控制流。关闭优化、某款编译器或某次运行没问题都不是正确性证据。

## 面试追问

为什么溢出检查 if (a + b < a) 对有符号数不可靠？答：表达式先发生溢出，检查已经太晚；应先比较边界或用受控宽类型。

## 动手练习与验收

编译器警告和 UBSan 跑正例；错误案例只作静态说明。验收：标注标准版本、行为类别与修复前提，不宣称动态工具能发现所有 UB。

## 来源与适用范围

- [C11 委员会草案 N1570（2011）](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：公开草案，作为 C11 基线；不是最新版 C 标准。
- [Clang：UndefinedBehaviorSanitizer](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html)：只能发现执行路径上的部分 UB。
