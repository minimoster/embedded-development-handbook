## 技术答案的依据与原创边界

- C++以固定公开N4659工作草案及GCC14.2官方规则核对内存顺序和对象/资源寿命；草案不是最新ISO正式标准。
- NVIC以CMSIS6.1.0、固定F407头文件和STM32F4 HAL宏核对编码；指定FreeRTOS V11.1.0 ARM_CM4F端口核对门槛。其他芯片/端口必须重查。
- Linux DMA以v6.6官方DMA API/DMAengine文档和固定源码核对；主机状态机不是内核驱动。
- HardFault以M4固定资料/CMSIS/Arm源码核对；离线合成副本不是目标采集器。

这些来源只支持章内实际核对的条款或路径，不宣称读完全部标准、内核或芯片手册。没有复制上游实现、大段注释或平台答案。已有许可证与公开引用继续保留。

## 验证层次不能混合

主机层包括严格C++17编译、有界真实线程测试、C++ ASan/UBSan（本受限环境显式关闭LSan），以及NVIC整数、DMA显式事件和HardFault合成副本的Python测试。默认LSan的新尝试实际因ptrace限制失败，不能称泄漏检查通过。线程压力结果不是内存模型形式证明；串行事件遍历不是并发驱动证明；范围检查也不是实际RAM可读性证明。

静态阅读器检查源码一致、分类、搜索、路由/锚点和离线代码资源。实际浏览器、远端CI和部署结果只有在对应候选完成后才另记；本文不预先冒称它们通过。统一入口见[主机实验](../../examples/README.md)，精确执行范围见[验证摘要](../../coverage/validation-summary.json)。

## 仍待继续的具体深度

这一轮补的是四个窄合同，不意味着这些大方向已经做完：C++多生产者/多消费者与回收、目标原子实现及ISR适用性；真实中断延迟、DMA/cache及芯片外设确认；完整驱动probe/remove、并发取消、PM、设备树与USB/PHY；真正的故障采集、符号化、长期板测与断电恢复仍需目标验证。网络的多缺口/SACK、完整TCP实现、DNS/TLS状态与安全工程也未由本轮完成。

原有专门深度缺口没有因为四个章名机械删减；未读、部分可见、媒体及重试耗尽的外部材料状态也没有被主机实验改成“已读”。[覆盖边界](coverage-boundaries.md)和[16篇选读路线](optional-depth.md)继续明确范围。本仓库不承诺覆盖所有公司、所有提问、所有芯片或所有源材料。
