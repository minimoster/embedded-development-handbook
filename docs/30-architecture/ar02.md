# AR02 · 链接脚本、Flash/RAM 与 VMA/LMA 怎么理解？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

链接脚本描述内存区域、段和符号。VMA 是运行时地址，LMA 是装载地址；常见 .data 在 Flash 保存初始值，在 RAM 运行。启动代码复制 .data 并清零 .bss，但必须以实际脚本和启动代码为准。

## 原理拆解

CPU 不会仅因段名字叫 .data 就自动完成复制。链接器生成起止符号，启动代码按这些边界初始化。栈、堆与保留区也需明确布局；外设和 DMA 对内存区可达性可能有额外限制。

## 例子与推演

例如 Flash 中保存三个初值，启动时从 _sidata 复制到 [_sdata,_edata)，再清零 [_sbss,_ebss)。noinit 区若需保留，必须同时通过脚本和启动代码排除，并验证复位类型。

## 常见误区与失败边界

“bss 不占 RAM”错误，它通常不需要保存同等长度初始字节的镜像，但会占运行时 RAM。不要凭 map 文件一个总数忽略堆栈碰撞。

## 面试追问

const 一定在 Flash 吗？答：语言层面不保证，布局由链接配置、目标和优化决定。

## 动手练习与验收

读一个受控主机 ELF 的段和符号，再画 MCU 布局。验收：区分镜像大小和运行 RAM；真实芯片地址需查该型号 RM。
