# AR05 · ABI、调用约定与栈对齐为什么会影响固件？

学习优先级：P1。先独立回答，再展开机制与验证。

## 直接回答

ABI 约定参数、返回值、寄存器保存、栈对齐和数据布局。语言相同不代表目标文件可互相链接；浮点 ABI、指令集、端序和运行库配置必须兼容。

## 原理拆解

AAPCS32对寄存器保存及公共接口栈约束有明确规定。soft通常通过库实现浮点运算；softfp允许硬件浮点指令，但二者采用基础AAPCS参数传递。hard使用相应VFP调用变体。仍需核对CPU/FPU能力、库与ELF属性；链接错误不能靠强行忽略来修复。

## 例子与推演

给工具链显式设置 -mcpu/-mthumb 及适用 -mfloat-abi/-mfpu，再用 readelf -A 核对属性。故障若出现在浮点库调用边界，应同时检查库版本和目标属性。

## 常见误区与失败边界

“编译都通过说明库兼容”错误。不要把 Cortex-M 的异常自动压栈与普通函数调用保存规则混成一份寄存器清单。

## 面试追问

某库能链接但调用后崩溃，先看什么？答：ABI、栈对齐、结构体布局、调用签名与初始化状态。

## 动手练习与验收

做一个 C/汇编或 C/C++ 边界接口并核对反汇编。验收：能说明接口的参数和保存责任，不要求记忆不适用内核的细节。
