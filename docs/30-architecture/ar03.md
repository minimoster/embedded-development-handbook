# AR03 · Cortex-M 从复位到 main 发生什么？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

典型 Cortex-M 复位从向量表取得初始 MSP 和复位处理入口，随后平台启动代码配置必要状态、初始化运行环境，最后进入 main。具体时钟、C++ 构造器与系统初始化顺序由工程启动文件决定。

## 原理拆解

向量表连接异常号和处理函数地址；链接脚本需保留启动段。默认弱定义可被同名处理函数覆盖。Bootloader 跳转到应用还涉及 MSP、向量表位置、正在活动的中断、外设和时钟状态，不能只调用入口函数。

## 例子与推演

用 ELF/map 核对向量表地址与 Reset_Handler；反汇编检查 .data/.bss 初始化以及是否调用静态构造器。记录 MCU 型号、Flash 起点和应用 offset，避免将另一系列地址照抄。

## 常见误区与失败边界

“main 是第一条执行代码”错误。把所有 Cortex-M 都描述为有完全相同 VTOR 能力也不准确，需查具体内核与设备实现。

## 面试追问

为什么 Bootloader 能启动自己，跳应用却 HardFault？答：检查入口地址、栈顶、Thumb 状态、向量表、段初始化和中断遗留状态。

## 动手练习与验收

纸面审核启动链，列出每个状态的建立者。验收：能指出一处符号或反汇编证据；本仓库不声称已在板上启动。
