# AR01 · 预处理、编译、汇编、链接各负责什么？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

预处理展开包含与宏；编译进行语义分析和优化并生成汇编/中间产物；汇编生成目标文件；链接按符号与布局规则合并目标及库。定位错误先分阶段，别把 undefined reference 当语法错误。

## 原理拆解

目标文件包含机器码、符号、重定位等信息；同名外部定义冲突通常在链接阶段暴露。头文件提供声明，定义需恰当组织；C 与 C++ 的语言链接不同，C 接口头可用 extern "C" 包围。

静态库archive通常由链接器按未解决符号提取所需对象成员，不是一律整库全部复制；whole-archive是另一个明确选项。动态库替换仍需ABI/依赖/符号兼容性。链接模式本身不自动决定程序更安全或运行更快，构建依赖追踪另见 [AR09](ar09.md)。

## 例子与推演

```cpp
#ifdef __cplusplus
extern "C" {
#endif
int sensor_read(void);
#ifdef __cplusplus
}
#endif
```
用 gcc -E、-S、-c 和 nm/readelf 分别观察阶段，不要求 MCU 硬件。

## 常见误区与失败边界

头文件加 include guard 只解决重复包含，不能把任意外部变量定义安全放进所有编译单元。宏没有类型安全，还可能重复求值。

## 面试追问

静态库链接顺序为什么可能重要？答：传统链接器按顺序提取满足未解析符号的成员，应检查工具链行为与组参数。

## 动手练习与验收

做两个源文件一个库，刻意制造缺定义与重复定义。验收：指出发生阶段，提供符号表证据和正确修复。
