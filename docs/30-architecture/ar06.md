# AR06 · 交叉编译怎样避免误链接主机库？

学习优先级：P0。先独立回答，再展开机制与验证。

## 直接回答

交叉编译使用为目标生成代码的编译器，并配套目标 sysroot、头文件与库。构建机和运行目标不同；配置期不能随意运行目标二进制。CMake toolchain 文件需要在初次配置时指定。

## 原理拆解

CMAKE_SYSTEM_NAME、编译器、sysroot 与 find root 策略分别影响目标识别、编译及依赖查找。已有构建缓存可能残留主机路径，改变工具链后通常使用新的构建目录。输出还要核对 ELF machine、解释器与依赖 ABI。

## 例子与推演

Linux 目标用目标 SDK 的编译器和 sysroot；裸机则可能需要 Generic 系统及特定 try_compile 设置。主机的 /usr/lib 不应偷偷进入目标链接。保留完整配置与编译命令。

## 常见误区与失败边界

“交叉编译成功就能运行”忽略内核接口、动态加载器、libc 和 CPU 特性。不要从不明来源拼凑工具链和目标库。

## 面试追问

为什么 configure 的测试可编译但无法运行？答：测试产物是目标架构代码，应使用受支持 emulator 或改用编译判断。

## 动手练习与验收

配置独立 toolchain 文件并用 readelf/file 核对输出。验收：证明依赖来自目标 sysroot，主机测试与目标固件分开。
